## 0. 지원 DB 와 DB 별 차이

| 항목 | MySQL | PostgreSQL | SQL Server |
|---|---|---|---|
| 드라이버 | mysql-nio (Swift) | postgres-nio (Swift, 결과 텍스트 형식 패치본) | FreeTDS DB-Library (앱에 포함, 빌드 시 `brew install freetds`) |
| 기본 포트 | 3306 | 5432 | 1433 |
| 사이드바 드롭다운 | DB | **스키마** (접속 DB 는 접속 설정에서 지정) | DB |
| 테이블 이름 | `table` | `table` (선택한 스키마 안) | dbo 는 `table`, 그 외 `schema.table` |
| 식별자 인용 | `` `x` `` | `"x"` | `[x]` |
| 자동 행 제한 | `LIMIT n` | `LIMIT n` | `SELECT TOP n` |
| 읽기전용 | 앱 검사 + `SET SESSION TRANSACTION READ ONLY` | 앱 검사 + `SET SESSION CHARACTERISTICS AS TRANSACTION READ ONLY` | **앱 검사만** (세션 설정 없음) |
| CREATE 문 보기 | 서버의 `SHOW CREATE TABLE` | 메타데이터로 생성 (CREATE TABLE + INDEX + COMMENT) | 메타데이터로 생성 (+ MS_Description) |
| 실행 계획 | `EXPLAIN` + `FORMAT=TREE` | `EXPLAIN` (QUERY PLAN 트리) | `SET SHOWPLAN_ALL ON` |
| 주의사항 분석 | type=ALL, filesort, temporary | Seq Scan, 디스크 정렬, 큰 Nested Loop | Table/Clustered Index Scan, Sort, Key Lookup |
| 인덱스 상세 | `SHOW INDEX` | pg_indexes + 사용 횟수/크기 | `sp_helpindex` |
| 프로시저 호출 틀 | `CALL p();` | `CALL p();` | `EXEC p;` |
| 기본값 입력 (ALTER) | 값 그대로 (`A` → `'A'`) | **SQL 식** (`'A'`, `now()`) | **SQL 식** (`('A')`, `(getdate())`) |
| 컬럼 위치 (AFTER) | 지원 | 미지원 (항상 맨 뒤) | 미지원 (항상 맨 뒤) |
| 코멘트 | `COMMENT` | `COMMENT ON` | 확장 속성 `MS_Description` |

- 한 번에 여러 문장 실행: PostgreSQL 드라이버는 스크립트를 문장 단위로 나눠 차례로 실행한다 (`$$ … $$` 함수 본문은 나누지 않음). SQL Server 는 배치로 한 번에 보낸다.
- 오류 번역: PostgreSQL SQLSTATE(28P01, 3D000, 42P01, 42703, 42601, 42501, 25006…), SQL Server 번호(18456, 4060, 208, 207, 102, 229, 20009…)에 한국어 해결 방법을 붙인다.
- 비밀번호 오류 재입력: MySQL 1045 / PostgreSQL 28P01 / SQL Server 18456.

## 1. 화면 구성

```
┌───────────────┬──────────────────────────────────────────────┐
│ 사이드바        │ [쿼리 | 스키마 비교]                           │
│ - 접속 목록     │ 탭 바                                         │
│ - DB 선택       │ SQL 편집기                                    │
│ - 테이블        │ ─────── (드래그로 높이 조절)                    │
│   - 컬럼        │ 결과 표                    │ 행 상세 (선택 시)  │
│   - 인덱스      │                                              │
│ - 뷰/프로시저…  ├──────────────────────────────────────────────┤
│ - 테이블 검색   │ 상태창 (⇧⌘L, 드래그로 높이 조절)                │
│               │ 상태 표시줄: 마지막 이벤트 · 오류 수 · [상태창]   │
└───────────────┴──────────────────────────────────────────────┘
```

- 사이드바와 본문 사이 경계는 드래그로 너비를 조절한다 (200 ~ 520pt).
- 편집기/결과, 결과/행 상세, 본문/상태창 경계도 모두 드래그로 조절한다.
  - AppKit 분할 뷰(VSplitView/HSplitView)를 겹쳐 쓰면 사이드바 조절이 꼬여서, 경계선은 직접 구현했다 (`ResizeHandle`).

## 2. 접속 관리

| 항목 | 설명 |
|---|---|
| DB 종류 | MySQL / PostgreSQL / SQL Server. 바꾸면 포트가 기본값으로 바뀐다 (직접 바꾼 포트는 유지) |
| 이름 | 사이드바에 보이는 이름 (옆에 MY / PG / MSSQL 표시) |
| 호스트 / 포트 | `localhost` 를 쓰면 IPv4(127.0.0.1) → IPv6(::1) 순서로 모두 시도한다 |
| 사용자 / 기본 DB | 기본 DB 를 비우면 접속 후 첫 번째 DB 를 연다 |
| TLS 사용 | 켜면 암호화 연결. **서버 인증서 확인**(기본 켬)은 [36. TLS 서버 인증서 확인](#36-tls-서버-인증서-확인) |
| 읽기전용 | [5. 읽기전용 모드](#5-읽기전용-모드) |
| 비밀번호 저장 | [3. 비밀번호 저장](#3-비밀번호-저장) |
| SSH 터널 | [4. SSH 터널](#4-ssh-터널) |

- **여러 접속을 동시에 열 수 있다.** 사이드바에서 접속을 누르면 다른 접속은 끊지 않고 연결(이미 연결돼 있으면 보기만 전환)한다.
  - **더블클릭** → 연결한 뒤 그 접속의 쿼리 탭으로 이동, 탭이 없으면 새 쿼리 탭 (스키마 비교 · 모델링 화면이면 쿼리 화면으로).
  - 접속 왼쪽 점: 초록 = 연결됨, 빨강 = 실패, 회색 = 안 됨. 오른쪽 숫자 = 그 접속의 쿼리 탭 수.
  - 접속 줄: [연결 상태] [DB 아이콘] 이름 [환경]. DB 아이콘은 각 DB 의 로고를 브랜드 색으로 (MySQL 돌고래, PostgreSQL 파랗게 채운 코끼리, Redis — Simple Icons, CC0). SQL Server 는 공식 로고를 쓸 수 없어 주황 DB 원통 + 렌치 · 드라이버 (GodDB 자체 그림). 마우스를 올리면 DB 이름.
  - 우클릭 → 새 쿼리 탭 / 다시 연결 / 연결 끊기 (연결 안 됐으면 연결) / 편집 / 복제 / 삭제.
  - 메뉴 "데이터베이스" → 보고 있는 접속 끊기, 모든 접속 끊기.
  - 툴바에 보고 있는 접속과 "열린 접속 N개" 표시.
- 접속을 끊어도 그 접속의 쿼리 탭은 남는다. 다시 연결하면 이어서 쓸 수 있다.
- **연결 테스트**: 저장하지 않고 연결해 MySQL 버전을 보여준다. 결과는 상태창에도 남는다.

## 3. 비밀번호 저장

| 설정 | 동작 |
|---|---|
| 비밀번호 저장 켬 (기본) | macOS 로그인 키체인에 저장 (서비스 `GodDB`, 계정 = 접속 ID). 다음부터 묻지 않는다 |
| 비밀번호 저장 끔 | 연결할 때마다 입력창이 뜬다. 입력한 값은 **앱을 끌 때까지만** 메모리에 기억한다 |

- 접속 편집 화면에 "키체인에 저장된 비밀번호가 있어요" 표시와 **저장된 비밀번호 지우기** 버튼이 있다.
- 비밀번호가 틀리면 (MySQL 1045) 바로 비밀번호 입력창이 다시 뜬다.
- 입력창에서도 "키체인에 저장" 여부를 고를 수 있다.
- 비밀번호 · 암호 칸 오른쪽 **눈 버튼**으로 입력한 값을 보이기 / 가리기.
  - 키체인에 저장된 비밀번호를 볼 때는 매번 **macOS 본인 확인**(Touch ID 또는 Mac 로그인 암호)을 거친다. 키체인이 "항상 허용"이어도 마찬가지.
  - 칸을 완전히 비우고 새로 입력한 값은 확인 없이 보인다. 한 글자만 지운 값은 저장된 비밀번호로 보고 확인을 거친다.
  - 저장된 비밀번호를 보면 상태창 · 로그 · 감사 로그에 "저장된 비밀번호 보기"가 남는다 (값은 남기지 않음).
- 비밀번호는 `profiles.json` 에 절대 기록하지 않는다.

> 참고: 앱을 새로 빌드하면 서명이 바뀌어서, 처음 연결할 때 macOS 가 키체인 접근 허용을 물을 수 있다. **항상 허용**을 누르면 된다.

## 4. SSH 터널

- Mac 의 `/usr/bin/ssh -N -L 127.0.0.1:<빈 포트>:<DB 호스트>:<DB 포트>` 로 터널을 연다.
- `~/.ssh/config`, `ssh-agent`, `known_hosts` 를 그대로 쓴다. 키 파일을 비우면 agent/설정 파일을 따른다.
- 옵션: `BatchMode=yes`(비밀번호 묻지 않음), `StrictHostKeyChecking=yes` + `UserKnownHostsFile="~/.ssh/known_hosts" "<GodDB known_hosts>"`, `ExitOnForwardFailure=yes`, `ServerAliveInterval=30`.
- 처음 접속하는 서버는 지문을 보여 주고 확인받는다 — [37. SSH 호스트 키 확인](#37-ssh-호스트-키-확인).
- 15초 안에 포트가 열리지 않거나 ssh 가 종료되면 ssh 의 오류 메시지를 그대로 보여준다.
- 지원: 키 파일 인증 / ssh-agent. **미지원: 비밀번호 방식 SSH.**

## 5. 읽기전용 모드

두 단계로 막는다.

1. **앱 검사**: 첫 키워드가 `SELECT / SHOW / DESC / DESCRIBE / EXPLAIN / USE / WITH` 일 때만 실행.
   - `INTO OUTFILE / DUMPFILE` 포함 시 차단, `WITH … UPDATE/DELETE…` 차단.
2. **서버 설정**: 연결 직후 `SET SESSION TRANSACTION READ ONLY` → 앱 검사를 우회해도 서버가 DML 을 거부 (오류 1792).

- 사이드바와 툴바에 빨간 **읽기전용** 표시.
- 테이블 수정(ALTER) 화면의 실행 버튼이 비활성화된다.

## 6. 스키마 브라우저

- 사이드바 상단 드롭다운으로 DB 를 바꾼다 (`information_schema`, `mysql`, `performance_schema`, `sys` 는 숨김).
- 테이블을 펼치면 컬럼(🔑 PK, 타입, NN)과 **인덱스 폴더**가 보인다.
- 테이블 더블클릭 → `SELECT * … LIMIT 500` 실행.
- 테이블 우클릭 메뉴

| 메뉴 | 동작 |
|---|---|
| 데이터 보기 (SELECT) | 현재 탭(비어 있으면) 또는 새 탭에서 SELECT 실행 |
| 테이블 수정 (ALTER)… | [10. 테이블 수정](#10-테이블-수정-alter) 화면 |
| CREATE 문 보기 | `SHOW CREATE TABLE` 결과를 **새 탭 편집기에 전체 텍스트로** 연다 (잘리지 않음, 하이라이트됨) |
| 인덱스 상세 보기 | `SHOW INDEX FROM` 실행 (카디널리티 등) |
| 이름 복사 | 클립보드로 복사 |

- 하단 **테이블 검색**은 테이블과 뷰/프로시저/함수/트리거 이름을 함께 거른다.
- `⇧⌘R` 또는 새로고침 버튼으로 다시 읽는다. CREATE/ALTER/DROP/RENAME/TRUNCATE 실행 후에는 자동으로 다시 읽는다.

## 7. 쿼리 편집기

- **쿼리 탭은 탭마다 접속 / DB(스키마)가 정해져 있다.** 탭에 `[MY/PG/MSSQL] 쿼리 N` 과 `접속명 / DB` 가 표시된다.
  - `+` 또는 `⌘T` → **사이드바에서 보고 있는 접속 / DB** 로 새 탭. 다른 접속을 누르고 `+` 하면 그 접속의 탭이 생긴다.
  - 탭을 고르면 사이드바도 그 탭의 접속 / DB 로 바뀐다. 사이드바에서 DB 를 바꾸면 보고 있는 탭의 DB 도 바뀐다.
  - 같은 접속의 탭끼리 DB 가 달라도 된다. 실행 직전에 탭의 DB 로 맞춘다 (`USE` / `search_path`).
  - 처음에는 탭이 없다 (접속 안 된 기본 "쿼리 1" 없음). 접속을 처음 연결하면 그 접속의 탭이 하나 열린다.
  - 연결이 끊긴 접속의 탭은 회색 점으로 표시되고, 실행하면 다시 연결하라고 안내한다.
  - 탭 우클릭 → 이 접속에 새 탭 / 탭 닫기 / 다른 탭 모두 닫기.
- 끌어서 바꾼 화면 경계 크기는 기억해서 모든 탭 · 다음 실행에 쓴다: 편집기 / 결과 높이, 행 상세 폭, 상태창 높이 · 로그 상세 폭, AI 어시스턴트 폭, ER 다이어그램 AI 패널 폭, 모델링 목록 폭 · 아래 편집기 높이, Redis Workbench 높이.
  - 메뉴 **보기 > 레이아웃 초기화** 로 모두 처음 크기로 되돌린다.
- 키워드·문자열·숫자·백틱 식별자·주석 하이라이트. 자동 따옴표 변환 등은 끔.
- **실행 대상**
  - `⌘↩` / ▶ 실행: 선택 영역이 있으면 → **선택한 부분만** 실행 (선택 안에 문장이 여러 개면 그 문장들을 차례로). 선택이 없으면 → **커서가 있는 문장 하나만** (편집기에서 강조된 문장)
  - `⌥⌘↩` / ⏩ 전체 실행: **편집기의 모든 문장을 위에서부터 차례로** 실행
  - 문장 구분은 세미콜론 기준 (따옴표·주석·PostgreSQL `$$ … $$` 안의 `;` 는 무시)
  - 중간 문장이 실패하면 그 자리에서 멈추고 "N번째 문장에서 멈췄어요 (앞의 N-1개는 실행됨)" 를 보여준다. 앞 문장 결과는 그대로 볼 수 있다.
  - **안전장치**: 전체 실행하는데 변경 문(INSERT/UPDATE/DELETE/DDL 등)이 섞여 있으면 실행 전에 확인창을 띄운다 (변경 문 미리보기 포함). 조회 문만 있으면 바로 실행.
  - **운영 접속 자동 끊기** (설정 > 일반 > 안전, 기본 30분 · 끔 / 10 / 30 / 60분): 운영 접속을 그 시간 동안 쓰지 않으면 끊는다. 사용 = 쿼리 · 페이지 · 내보내기 · 스키마 읽기 · Redis 명령 (자동 새로고침 · 화면 보기는 사용이 아님). 커밋하지 않은 변경이 있으면 끊지 않고 한 번 알린다. 실행 · 내보내기 중이면 끝날 때까지 미룬다. 쿼리 탭은 남고, 다시 실행하면 다시 연결한다. 감사 로그 `접속해제 | 자동 (30분 미사용)`.
  - **위험한 명령 확인**: WHERE 없는 DELETE / UPDATE, TRUNCATE, DROP (Redis 는 FLUSHALL · FLUSHDB · KEYS 등) 은 한 문장이어도 실행 전에 확인한다. **설정 > 일반 > 안전 > 위험한 명령 실행 전 확인** 으로 끌 수 있다 (기본 켬, 켜고 끈 기록은 감사 로그에 남음). 운영 접속에서 데이터를 바꾸는 확인은 이 설정과 관계없이 항상 뜬다.
- **결과 탭**: 여러 문장을 실행하면 결과 영역 위에 `1 SELECT 3행 · 2 UPDATE 실행 완료 …` 형태의 탭이 생긴다. 기본으로 결과 표가 있는 마지막 결과를 보여준다.
- **실행 계획** (`⇧⌘↩`)은 여전히 선택 영역 또는 커서가 있는 문장 하나만 대상으로 한다.
- **LIMIT 자동 부여**: LIMIT 이 없는 SELECT 에만 붙인다 (100 / 500 / 1000 / 5000 / 제한 없음). `FOR UPDATE`, `INTO` 가 있으면 붙이지 않는다.

### Tab 자동완성

| 상황 | 후보 |
|---|---|
| `m.` / `m.em` (별칭 또는 테이블명 뒤 점) | 그 테이블의 컬럼만 (컬럼 순서대로) |
| `FROM` / `JOIN` / `UPDATE` / `INTO` / `TABLE` / `DESC` 바로 뒤 | 테이블, 뷰 우선 |
| 그 외 | 구문에 나온 테이블의 컬럼 → 키워드·함수 → 테이블 → 뷰/프로시저/함수 |

- 별칭 해석: `FROM tb_member m`, `JOIN tb_order AS o`, `FROM a x, b y`, `shop.tb_member` 형식 지원. `WHERE`/`ON` 등은 별칭으로 보지 않는다.
- 동작
  - 후보 1개 → 바로 채움
  - 후보 여러 개인데 공통 앞부분이 더 길면 → 공통 부분까지 채움 (한 번 더 Tab 하면 목록)
  - 그 외 → macOS 자동완성 목록 (↑↓ 선택, ↩ 확정, Esc 취소)
  - 후보 없음 → 경고음
  - 커서 앞이 공백이면 → 공백 4칸 (들여쓰기)
- 키워드 대소문자: 소문자로 입력하면 소문자 키워드(`sel` → `select`), 대문자면 대문자.
- 후보는 현재 선택된 DB 의 스키마 기준 (최대 50개).

- **결과 행 수 "제한 없음"**: 보이지 않게 1,000행씩 나눠 받고, 표를 끝까지 스크롤하면 다음 행을 이어 붙인다 (화면 최대 200,000행 — 넘으면 안내, 전체는 [내보내기]).
- **큰 값 보호**: 한 칸이 100만 자를 넘으면 표에는 앞부분만 담고(편집 막음), 내보내기는 전체를 저장한다. Redis 문자열은 1MB 넘으면 앞 1MB 만 보여주고 편집을 막는다.
- **트랜잭션 (자동 커밋 / 수동 커밋)** — 쿼리 도구 막대의 **자동 커밋** 체크박스 (접속 단위, 연결할 때마다 켜짐, Redis·읽기전용 접속에는 없음)
  - 끄면 INSERT · UPDATE · DELETE 같은 쓰기 문장을 실행할 때 트랜잭션을 열고, **[커밋]** 해야 DB 에 반영된다. 조회만 하면 트랜잭션을 열지 않는다.
  - 열려 있는 동안 주황색 `트랜잭션 · 변경 N건` + **[커밋] [롤백]**. 롤백하면 열린 결과를 다시 읽는다.
  - 결과 표 편집 적용도 열린 트랜잭션에 합류한다 (따로 커밋하지 않음).
  - 편집기에 직접 `COMMIT` / `ROLLBACK` / `BEGIN` 을 써도 상태가 맞춰진다. **MySQL 은 CREATE · ALTER · DROP 이 자동 커밋**된다.
  - 열린 트랜잭션이 있는데 자동 커밋을 켜거나 연결을 끊으면 커밋/롤백을 묻는다. 앱을 끄면 "롤백하고 종료" 를 묻는다.
  - 감사 로그: 자동 커밋 켬/끔(설정), 커밋 · 롤백(실행, 변경 건수).

## 8. 결과 표와 행 상세

- 결과 표의 행을 클릭하면 오른쪽에 **행 상세** 패널이 열린다.
  - 모든 컬럼의 **전체 값**을 줄바꿈 그대로 보여준다 (텍스트 선택 가능).
  - 컬럼별 글자 수, 값 복사 버튼.
  - 패널 너비는 경계를 드래그해 조절.
- 결과가 1행이면 (예: `SHOW CREATE …`) 상세 패널이 자동으로 열린다.

### 페이징 (500행 단위)
- SELECT 결과는 **페이지 크기(기본 500행) 단위**로 가져온다. 툴바 "페이지" 에서 100 / 500 / 1000 / 5000 / 제한 없음.
- 결과 아래: `⏮ ◀ 501–1,000행 ▶ ⏭` · "2페이지 · 더 있음/끝" · **전체 행 수** 버튼.
  - 다음 페이지가 있는지는 페이지 크기 + 1 행을 요청해서 알아낸다.
  - **전체 행 수**는 `SELECT COUNT(*) FROM (원래 쿼리)` 로 센다 (버튼을 눌렀을 때만, 큰 테이블은 오래 걸릴 수 있음). 세고 나면 "전체 N행 · 3/12페이지" 와 마지막 페이지 버튼이 보인다.
  - 페이지를 넘길 때마다 같은 쿼리를 OFFSET 만 바꿔 다시 실행한다 (그사이 데이터가 바뀌면 경계가 어긋날 수 있음).
- DB 별: MySQL·PostgreSQL `LIMIT n+1 OFFSET m` / SQL Server 는 맨 바깥 ORDER BY 가 있으면 `OFFSET m ROWS FETCH NEXT n+1 ROWS ONLY`, 없으면 `TOP (m+n+1)` 로 가져와 앞부분을 버린다.
- 이미 `LIMIT / TOP / OFFSET / FETCH / INTO / FOR UPDATE` 가 있는 쿼리, SELECT 가 아닌 문장은 그대로 실행한다 (페이징 없음).
- 행 상세의 "N번째 행" 과 행 범위는 전체 기준 번호다. CSV 복사는 지금 보이는 페이지만.
- 표 셀은 한 줄 미리보기 (줄바꿈은 `⏎`, 200자 초과 시 `…`). NULL 은 흐리게 `NULL`.
- 우클릭 → 선택 행 CSV 복사.
- 하단 **내보내기** → **내보내기 설정 창**(형식 카드 6개 · 범위 · 형식별 옵션) → **저장 위치 선택…** → 저장 창 (파일 이름 `테이블명_날짜시각.확장자`, 마지막에 고른 형식을 기억):
  - **형식**: CSV / TSV / **Excel (.xlsx)** / JSON / SQL INSERT / Markdown
    - CSV·TSV: 엑셀 호환 UTF-8 BOM 선택 (기본 켬), 줄바꿈 CRLF. TSV 는 값 안의 탭·줄바꿈을 공백으로.
    - Excel: 머리글 굵게·고정, 숫자로 바꿔도 값이 그대로인 것만 숫자 셀(앞자리 0, 16자리 이상, 지수 표기는 문자). 시트 최대 1,048,575행 — 넘으면 앞까지만 저장하고 경고.
    - JSON: 행마다 `{컬럼: 값}` 객체, NULL 은 `null`, 같은 이름 컬럼은 `_2` 를 붙인다.
    - SQL INSERT: 대상 테이블 이름 입력, 100행씩 한 문장, DB 별 인용 부호, 값은 문자열 리터럴.
    - Markdown: Confluence · Jira 붙여넣기용 표 (`|` 와 줄바꿈 이스케이프).
  - **범위**: **쿼리 전체 결과** / **지금 보이는 행만**. 결과가 한 페이지뿐이면 보이는 행 = 전체.
    - 전체 결과는 **화면 페이지가 아니라 쿼리의 전체 데이터**를 **5,000행씩 나눠 다시 조회**하며 파일에 바로 쓴다 (메모리에 전부 올리지 않음).
    - 시작 전에 `COUNT(*)` 로 전체 행 수를 확인 → 결과 아래 줄에 `n / 전체행` 진행률과 **취소**(쓰던 파일 삭제).
    - 페이지 사이에 행이 빠지거나 겹치지 않도록: 화면 정렬(서버 정렬)이나 SQL 의 ORDER BY 가 있으면 그대로, 없으면 결과에 있는 **단일 컬럼 기본 키로 정렬**. 둘 다 없으면 저장 창과 상태창에 경고.
    - 끝나면 "전체 데이터 N행 (COUNT 와 일치)" 또는 개수가 다르면 경고를 상태창·로그에 남긴다.

## 9. 실행 계획 (EXPLAIN)

- **실행 계획** 버튼 또는 `⇧⌘↩`: 커서 구문 앞에 `EXPLAIN` 을 붙여 실행한다.
- 결과 위에 **주의사항 요약**:

| 조건 | 메시지 |
|---|---|
| `type = ALL` | 풀 테이블 스캔 (예상 행 수) — 인덱스 확인 |
| `type = index` | 인덱스 풀 스캔 |
| `possible_keys` 있는데 `key` 없음 | 사용 가능한 인덱스를 쓰지 않음 |
| `Extra` 에 `Using filesort` | ORDER BY 인덱스 검토 |
| `Extra` 에 `Using temporary` | GROUP BY / DISTINCT 검토 |

- MySQL 8.0.16 이상이면 `EXPLAIN FORMAT=TREE` 결과를 **트리로 보기** 스위치로 볼 수 있다.
- 실행 계획 결과와 주의사항은 상태창에도 남는다.

## 10. 테이블 수정 (ALTER)

테이블 우클릭 → **테이블 수정 (ALTER)…**

- 화면 구성: 왼쪽 트리(테이블 > columns / keys / indexes / foreign keys) + 도구(+ − 복제 ↑ ↓), 오른쪽 고른 항목의 속성, 아래 미리보기.
- **컬럼**: 이름 / 코멘트 / 데이터 타입(자주 쓰는 타입 메뉴) / Not Null / Auto Increment / 기본 키 / 기본값 / On Update · 기타 Extra(MySQL). 추가, 삭제, 복제, 순서 이동.
  - 새 컬럼은 "새", 바뀐 항목은 주황 점, 지울 컬럼은 빨간 취소선(눌러서 되살리기).
- **인덱스**: 이름 / UNIQUE / 컬럼(순서대로 추가·위로·빼기). PRIMARY 는 컬럼만 바꿀 수 있다. 외래 키는 보기만.
- **테이블 코멘트** 편집.
- 아래 **미리보기 SQL** 이 실시간으로 바뀐다. 하나의 `ALTER TABLE` 문으로 만든다.

| 변경 | 생성되는 절 |
|---|---|
| 인덱스 삭제 / 변경 | `DROP INDEX` (변경은 DROP 후 ADD) |
| 컬럼 삭제 | `DROP COLUMN` |
| 컬럼 이름 변경 | `CHANGE COLUMN old new …` |
| 컬럼 속성 변경 | `MODIFY COLUMN …` |
| 컬럼 추가 | `ADD COLUMN … AFTER 앞컬럼` (맨 앞이면 `FIRST`) |
| 인덱스 추가 | `ADD [UNIQUE] INDEX` / `ADD PRIMARY KEY` |
| 코멘트 | `COMMENT = '…'` |

- 검증: 빈 이름/타입, 중복 컬럼명, 인덱스의 없는 컬럼 → 미리보기에 빨간 오류, 실행 불가.
- 버튼
  - **쿼리 탭으로 열기**: 실행하지 않고 SQL 만 새 탭에 연다.
  - **실행…**: 확인창(접속명/DB 표시, "컬럼 삭제는 되돌릴 수 없음") 후 실행 → 성공 시 스키마 자동 새로고침, 상태창 기록.
  - 읽기전용 접속이면 실행 버튼 비활성.

> 컬럼 순서 이동만 한 경우(이름/속성 변경 없음)는 아직 ALTER 를 만들지 않는다.

## 11. 인덱스 보기

- 사이드바: 테이블 > **인덱스 N** 폴더에 인덱스 이름, 컬럼 순서, UQ/PK 표시.
- 인덱스 폴더 또는 테이블 우클릭 → **인덱스 상세 보기**: `SHOW INDEX FROM` 결과(카디널리티, Seq, Null, Index_type 등)를 새 탭에.

## 12. 뷰 / 프로시저 / 함수 / 트리거

- 사이드바에 종류별 섹션으로 표시 (있을 때만).
- 더블클릭 또는 우클릭 → **정의 보기**: `SHOW CREATE VIEW/PROCEDURE/FUNCTION/TRIGGER` 의 본문을 **새 탭 편집기에 전체 텍스트로** 연다.
- 뷰: 데이터 보기(SELECT). 프로시저: **CALL 문 만들기**.
- 마우스를 올리면 코멘트(트리거는 `BEFORE INSERT ON 테이블`)가 보인다.

## 13. 스키마 비교

- 기준 접속/DB → 대상 접속/DB 를 골라 **비교**.
  - 접속 선택 목록: [DB 아이콘] 이름 · 환경 (예: `회원 DB · 운영`), 그룹이 있으면 그룹별로 묶는다. 고른 접속 옆에 사이드바와 같은 색 환경 표시.
  - 연결 시간 제한: DB 서버가 **15초** 안에 연결되지 않으면 (SSH 터널은 따로 15초) 어느 쪽(기준/대상)이 실패했는지 오류를 보여 주고 **[다시 시도]**. 읽는 중에는 **[취소]**. 일반 접속에도 같은 시간 제한이 걸린다.
- 결과: 일치 테이블 수 / 다름 / 누락, "대상에만 있는 항목" 체크로 참고 항목 표시.
- 항목 여러 개 선택: ⌘ · ⇧ 클릭, ⌘A 또는 오른쪽 클릭 > **모두 선택**. ⌘C · 오른쪽 클릭 > **복사** · **선택한 N개 SQL 복사** 는 고른 항목들의 보정 SQL 을 목록 순서대로 빈 줄로 이어 복사한다 (참고용 항목은 건너뜀).

| 종류 | 보정 SQL |
|---|---|
| 테이블 없음 | 기준 DB 의 `SHOW CREATE TABLE` |
| 컬럼 없음 | `ADD COLUMN … AFTER` |
| 컬럼 다름 (타입/NULL/기본값/Extra/코멘트) | `MODIFY COLUMN` |
| 테이블 코멘트 다름 | `COMMENT =` (PostgreSQL `COMMENT ON TABLE`, SQL Server `MS_Description` 확장 속성) |
| 인덱스 없음 / 다름 | `ADD INDEX` / `DROP INDEX, ADD INDEX` |
| 대상에만 있음 | 없음 (참고용, **DROP 은 만들지 않음**) |

- **자동 실행하지 않는다.** 전체 SQL 복사 또는 쿼리 탭으로 열어 검토 후 실행.
- PostgreSQL 은 DB 대신 스키마를 비교한다 (비우면 `public`). serial 컬럼이 있는 테이블 · 컬럼을 만들 때는 시퀀스도 함께 만든다.
- SQL Server 는 기본값을 바꿀 때 기존 기본값 제약조건을 이름으로 찾아 지운 뒤 새로 단다.

## 14. 상태창 (로그)

- 창 하단 **상태 표시줄**: 마지막 이벤트 한 줄, 오류 건수, 상태창 열기 버튼 (`⇧⌘L`).
- **상태창**: 시간 · 종류(접속/쿼리/스키마/비교/앱) · 메시지 목록, 오른쪽에 상세.
  - 상세: 💡 해결 방법, 실행한 SQL, 원본 오류.
  - **오류가 나면 자동으로 열리고** 해당 항목이 선택된다.
  - 오류만 보기, 항목 복사, 전체 복사, 지우기, 로그 폴더 열기. 화면에는 최대 1,000건 (앱 종료 시 사라짐).
- **감사 로그 파일** (설정 > 일반 > 로그 > "로그 파일 남기기", 기본 켜짐, **보관 기간**: 영구(기본) / 3개월 / 6개월 / 1년 — 지난 파일은 자동 삭제, 최소 90일): 나중에 **누가 · 언제 · 어느 DB 에 · 무엇을 했는지** 분석하는 용도. 상태창(화면)은 자세히, 파일은 **한 줄 = 한 행위**로 짧게.
  - 무결성: 줄마다 무결성 값과 이 PC 기기 키 서명이 마지막 두 칸에 붙는다 (날짜 파일끼리도 연결).
  - 위치: `~/Library/Logs/GodDB/goddb-audit-YYYY-MM-DD.tsv` (권한 600, **영구 보관** — 감사 기록이라 기본은 자동 삭제하지 않음). 예전 `goddb-YYYY-MM-DD.log` 파일은 그대로 둔다.
  - 형식: **탭으로 나눈 6칸** (엑셀로 바로 열어 필터·정렬). 첫 줄 머리글, UTF-8 BOM.

    | 시각 | 사용자@PC | 구분 | 대상 | 결과 | 내용 |
    |---|---|---|---|---|---|
    | 2026-11-13 14:46:25.398 | kim@MacBook | 조회 | dev/shop | 1행 · 3ms | SELECT * FROM `tb_member` |
    | 2026-11-13 14:50:02.110 | kim@MacBook | 수정 | dev/shop | 결과 편집 1/2 (한 트랜잭션) | UPDATE `tb_member` SET … WHERE … |
    | 2026-11-13 14:51:10.004 | kim@MacBook | 삭제 | redis_dev db0 | 키 삭제 · 21ms | DEL LOGIN_FAIL:kim |
    | 2026-11-13 14:52:00.000 | kim@MacBook | AI | dev/shop | 어시스턴트 답변 · 9초 · qwen3:30b | |

  - **구분**: 앱시작 · 접속 · 접속해제 · 조회 · 추가 · 수정 · 삭제 · 구조변경 · 권한 · 실행 · 내보내기 · 비교 · AI · 설정
    - SQL 은 첫 키워드로 자동 분류 (SELECT/SHOW → 조회, INSERT → 추가, UPDATE/REPLACE/MERGE → 수정, DELETE/TRUNCATE → 삭제, CREATE/ALTER/DROP/RENAME → 구조변경, GRANT/REVOKE → 권한, 그 밖 → 실행). Redis 는 명령으로 (GET/SCAN → 조회, SET/EXPIRE → 수정, DEL/FLUSHDB → 삭제).
    - 여러 문장 스크립트, 결과 편집(한 트랜잭션)은 **문장마다 한 줄**.
    - 실패해도 같은 구분으로 남고 결과 칸이 `실패: 사유`.
  - **대상**: `접속이름/DB` (Redis 는 `접속이름 db번호`). **내용**: 실행한 SQL·명령을 한 줄로 편 것 (2만 자 넘으면 자름).
  - **앱시작** 줄: 앱 버전, 계정(전체 이름), 컴퓨터 이름, 호스트 이름, macOS 버전, 이 PC 의 IP 전체(인터페이스, VPN 여부).
  - **접속** 줄: 그 순간 이 PC 에서 나가는 IP 와 경로 (`client 10.x.x.x → ssh 바스티온:22 → db:3306`). 외부 서비스에 묻지 않으므로 공인 IP 는 남기지 않는다.
  - **AI** 는 요약 한 줄만 (`AI 어시스턴트 답변 · 9초 · 모델`). 질문·프롬프트(테이블 구조·실행 계획)·답변 내용은 파일에 남기지 않는다.
  - 남지 않는 것: 조회 결과 행, 화면 이동(페이지 넘김·정렬·DDL 보기·다이어그램 열기), Redis 자동 새로고침. (단, 실행한 SQL 문장 안에 쓴 값은 그대로 남는다)
- **문제 보고** (도움말 > 문제 보고…, 상태창의 🐞 버튼): 제목 · DB 종류 · 재현 방법 · 기대/실제를 쓰고, 버전·macOS·칩, **최근 오류 20건**, **크래시 보고서 요약**(최근 3개, 종료된 스레드 위 12줄)을 함께 담아 **GitHub 버그 신고 화면을 미리 채워 브라우저로 연다** (서버 없음, GitHub 로그인 필요).
  - 호스트 이름 · IP · 이메일 · 계정 · 홈 경로는 자동으로 가리고(`<host>`, `<ip>` …), 보내기 전에 내용을 직접 고칠 수 있다. [복사] 로 클립보드에 담을 수도 있다.
- 오류 번역 예시

| 원본 | 표시 |
|---|---|
| `IOError` ECONNREFUSED | 서버가 연결을 거부했어요 + 호스트/포트/서버 확인 |

## 21. 결과 데이터 편집

- **편집 가능 조건**: 테이블 하나만 조회한 SELECT (JOIN·GROUP BY·DISTINCT·UNION·HAVING·서브쿼리 없음), 테이블에 기본 키가 있고 결과에 기본 키 컬럼이 포함, 읽기전용 접속이 아님. 아니면 결과 위에 "편집 불가: 이유" 표시.
- 결과 위 편집 막대: `행 추가` · `선택 행 삭제`(다시 누르면 해제) · `변경 N건` · `되돌리기` · `적용…`
- **칸 그 자리 편집**: 칸을 **더블클릭**하면 그 칸이 입력란이 된다 (지금 값이 선택된 채, 표와 같은 고정폭 글꼴).
  - `↩` 넣기 · `Esc` 취소 · `Tab` / `⇧Tab` 넣고 같은 행의 다음 / 앞 칸 · 다른 곳 클릭 넣기. 글자를 바꾸지 않았으면 변경으로 남기지 않는다.
  - 넣은 값은 오른쪽 패널에서 고친 것과 똑같이 변경에 들어간다 (주황 표시 · `변경 N건` · 되돌리기 · 적용… 미리보기).
  - 입력란을 비우면 **빈 문자열**이다 (NULL 아님). NULL 은 칸 **우클릭 → NULL 로 설정 (컬럼)** (여러 행을 골랐으면 모두) 또는 패널의 NULL 체크.
  - 새 행(행 추가)의 칸도 같은 방법으로 고친다. 아무것도 안 쓰고 끝내면 `(기본값)` 그대로.
  - 바이너리 칸은 `0x…` 로 넣으면 바이너리로 저장 (패널과 같은 규칙). JSON 칸은 원문 글자를 그대로 고친다 (JSON 보기는 패널에서).
  - 그 자리에서 고치지 않는 칸 (더블클릭하면 예전처럼 행을 골라 패널을 연다): 편집 불가 결과, 테이블 컬럼이 아닌 결과 컬럼(계산식 등), 삭제 표시한 행, **여러 줄 값**(패널에서 고친다), 칸 밖(행의 빈 곳).
  - 입력란은 고치는 칸 하나에만 만든다 (행이 많아도 느려지지 않음). 편집 막대 버튼 · 페이지 이동 · 헤더 정렬을 누르면 고치던 값을 먼저 넣는다.
- **행 편집 패널 열기**: 행을 **클릭**해 고르면 오른쪽에 열린다 (1행 결과는 자동). 행 **우클릭** → 이 행 편집 / NULL 로 설정 / 행 추가 / 선택 행 삭제(삭제 표시 해제) / 행 복사(CSV). 편집할 수 없는 결과는 더블클릭해도 행 상세를 연다.
- 오른쪽 **행 편집** 패널에서 값 수정(여러 줄 포함), NULL 지정, (새 행) DB 기본값 사용. 기본 키 컬럼은 🔑 표시.
- 표시: 바뀐 셀 주황 굵게, 새 행 초록, 삭제 표시 빨간 취소선, 새 행의 입력 안 한 칸 `(기본값)`.
- **적용…** → 실행할 DELETE / UPDATE / INSERT 미리보기 → **한 트랜잭션**으로 실행, 하나라도 실패하면 전부 ROLLBACK → 성공하면 같은 페이지를 다시 읽는다.
  - WHERE 는 기본 키로만 만든다. 값은 문자열 리터럴로 넣고 DB 가 컬럼 타입으로 변환한다.
  - 바이너리 컬럼에 `0x…` 를 넣으면 바이너리로 저장 (MySQL `X'…'`, PostgreSQL `decode('…','hex')`, SQL Server `0x…`).
- 변경이 남아 있으면 페이지 이동이 막힌다 (적용하거나 되돌린 뒤 이동).

### 바이너리 표시
- varbinary / binary / BLOB / bytea / image 는 **`0xCD01FF…` 16진수**로 보인다.
- SQL Server 는 연결 직후 표준 세션 설정(`ANSI_PADDING`, `ANSI_NULLS`, `ANSI_WARNINGS`, `ANSI_NULL_DFLT_ON`, `CONCAT_NULL_YIELDS_NULL`, `QUOTED_IDENTIFIER`, `ARITHABORT` ON)을 켠다. DB-Library 기본값은 꺼져 있어서 varbinary 끝의 0 이 잘리는 등 다른 클라이언트와 다르게 동작했다.

## 22. 테이블 이름 변경 · 삭제 · 생성문 새로고침

- 테이블 우클릭 → **이름 변경…** : 새 이름 입력, 실행 SQL 미리보기 (MySQL `RENAME TABLE`, PostgreSQL `ALTER TABLE … RENAME TO`, SQL Server `sp_rename`). 열려 있던 그 테이블의 DDL 탭 이름도 바뀐다.
- 테이블 우클릭 → **삭제 (DROP)…** : 테이블 이름을 그대로 입력해야 삭제 버튼이 켜진다. 되돌릴 수 없음 경고.
- 읽기전용 접속에서는 두 메뉴가 꺼진다. 성공하면 사이드바 스키마를 다시 읽는다.
- DDL·정의 탭(CREATE 문 보기, 뷰/프로시저/함수/트리거 정의)의 툴바에 **생성문 새로고침** 버튼: DB 에서 다시 읽어 편집기 내용을 바꾼다 (테이블은 스키마도 새로 읽음).

### 헤더 클릭 정렬
- 결과 표 헤더를 누르면 오름차순, 다시 누르면 내림차순 (헤더에 화살표).
- **쿼리를 다시 실행해서 정렬한다**: `SELECT * FROM (원래 쿼리) AS goddb_sort ORDER BY 컬럼 ASC|DESC` → 첫 페이지부터. 페이지를 넘겨도 정렬 유지.
  - 원래 쿼리의 맨 바깥 ORDER BY 는 뺀다 (단 LIMIT/TOP/OFFSET 이 있으면 결과 집합이 바뀌지 않게 그대로 둔다).
  - SHOW 처럼 감쌀 수 없는 결과만 받아 온 행을 앱에서 정렬 (NULL 먼저, 숫자는 숫자 크기).
- 편집 중인 변경이 있으면 정렬 전에 적용하거나 되돌려야 한다. 실행한 정렬 SQL 은 상태창에 남는다.

### 결과 영역 hover
- 마우스가 올라간 **행을 강조**한다.
- 페이지 이동·CSV 복사·전체 행 수·결과 탭·행 상세 버튼: 올리면 강조색 배경과 테두리, 누르면 더 진해지며 살짝 작아진다.
- 페이지 이동/행 수 세기 중에는 결과 표는 그대로 두고 페이지 바에만 로딩 표시.

## 23. ER 다이어그램

- 여는 방법
  - 테이블 우클릭 → **다이어그램 보기**: 그 테이블 + 외래 키(또는 추정 관계)로 바로 이어진 테이블. 중심 테이블은 보라색.
  - 사이드바에서 테이블을 **⌘/⇧ 클릭으로 여러 개 선택** → 머리글의 다이어그램 버튼, 또는 고른 테이블 중 하나를 우클릭 → "다이어그램 보기 (선택한 N개)":
    고른 테이블은 **관계가 없어도 모두 따로** 보이고(보라색), 관계(외래 키·추정)가 있으면 **이어진 테이블도 함께**(파란색) 그린다.
  - 아무것도 고르지 않고 머리글의 다이어그램 버튼 → **스키마 전체** (최대 200개 테이블).
- **이름 표시**: 물리명(실제 이름) / 논리명(코멘트 첫 줄) / 둘 다. 코멘트가 없으면 물리명을 흐리게(기울여) 보여준다. 선택은 기억된다.
- **관계 추정** (기본 켬): 외래 키 제약이 없는 DB 를 위해, 컬럼 이름이 다른 테이블의 **단일 컬럼 기본 키 이름과 같으면** 관계로 보고 **점선**으로 그린다.
  - 자기 기본 키, 이미 진짜 외래 키가 있는 컬럼, 흔한 이름(id, seq, no, code …)은 제외.
  - 같은 기본 키 이름을 가진 테이블이 여럿이면 테이블 이름이 가장 비슷한 하나만 (애매하면 그리지 않음).
  - 진짜 외래 키는 실선, 추정은 점선. 툴바 체크박스로 끌 수 있다.
- 별도 창으로 열리고 여러 개를 동시에 띄울 수 있다. 연 순간의 스키마를 그린다 (구조가 바뀌면 다시 열기).
- 테이블 카드: 이름, 컬럼(🔑 기본 키, 🔗 외래 키 컬럼, 타입). 컬럼 24개 넘으면 "… N개 더".
- 관계선: 외래 키 컬럼 → 참조 컬럼. 자식 쪽 까마귀발, 부모 쪽 막대. 자기 참조는 고리 모양.
- 배치: 참조되는 테이블(부모)을 왼쪽, 참조하는 테이블(자식)을 오른쪽 열에. 관계 없는 테이블은 아래에 격자.
- 열 때 모든 테이블이 한 화면에 보이도록 자동으로 배율을 맞춘다 (툴바 "화면에 맞추기"로 다시).
- 조작: 카드 끌어서 이동, 마우스를 올리면 그 테이블의 관계만 강조, 확대/축소(30~200%), 자동 정렬, **PNG 저장**(2배 해상도).
- 외래 키 읽기 (같은 DB/스키마 안의 참조만): MySQL `information_schema.KEY_COLUMN_USAGE`, PostgreSQL `pg_constraint`, SQL Server `sys.foreign_keys`. 여러 컬럼 외래 키 지원.
- **AI 분석** (툴바 "AI 분석" → 오른쪽 패널, 너비 조절 가능): 설정 > AI 의 로컬 Ollama 와 모델을 쓴다.
  - "관계 분석 시작": 도메인·핵심 테이블, 관계별 카디널리티, FK 가 빠진 관계·인덱스 없는 FK 컬럼, 모델링 문제, 대표 JOIN 쿼리
  - 채팅: 이어서 자유롭게 질문 (Enter 로 보내기, 예시 질문 버튼). 대화 맥락을 기억하고, 답변 복사 / 답변의 SQL 을 쿼리 편집기에 넣기
  - **대화 기록**: 다이어그램(접속 · DB · 테이블 묶음)마다 저장해서 다시 열면 마지막 대화가 그대로 보인다 (분석이 오래 걸리므로). 🗨️+ "새 대화", 🕘 이전 대화 목록에서 열기/삭제, "이 다이어그램의 대화 모두 삭제". 90일 지난 대화는 자동 삭제. 위치 `~/Library/Application Support/GodDB/diagram-chats/` (권한 600)
  - 보내는 것: 다이어그램에 있는 테이블의 컬럼·타입·PK·NULL·코멘트·인덱스, 선언된 FK, 추정 관계. **데이터 행은 보내지 않는다.** 스키마가 크면 컬럼 목록을 줄여서 보낸다 (약 4만 자).

## 24. 접속 정보 내보내기 · 가져오기

- 사이드바 **접속** 목록 아래 ⇅ 메뉴 → "접속 정보 내보내기…" / "접속 정보 가져오기…"
- **내보내기**: 내보낼 접속을 체크 → 저장 위치 선택 → `goddb-connections-YYYYMMDD.json` (권한 600)
  - 기본은 비밀번호를 넣지 않는다. 받는 쪽에서 처음 연결할 때 입력.
  - "비밀번호 포함" 을 켜면 정한 암호(8자 이상)로 잠근다: PBKDF2-SHA256(20만 회) → AES-256-GCM. 암호는 파일에 없으니 따로 전달.
  - SSH 개인키 파일은 넣지 않고 경로만 넣는다.
- **가져오기**: 파일 선택 → 목록에서 가져올 접속 체크
  - 새 접속은 "새로 추가"(기본 체크), 같은 접속(같은 id)이 이미 있으면 "이미 있음 → 덮어씀"(기본 해제)
  - 이름이 다른 접속과 겹치면 ` (2)` 를 붙인다.
  - 비밀번호가 들어 있으면 암호를 넣어 함께 가져온다 (비우면 비밀번호 없이). 접속의 "비밀번호 저장" 설정에 따라 키체인 또는 실행 중에만 보관.
- 내보내기·가져오기는 상태창과 로그 파일에 남는다.
- **DataGrip 붙여넣기**: DataGrip 에서 데이터 소스를 고르고 ⌘C → GodDB 사이드바에서 ⌘V (또는 ⇅ 메뉴 > "DataGrip 접속 정보 붙여넣기")
  - `jdbc-url` 에서 종류·호스트·포트·DB·TLS 옵션, `user-name`, 이름, uuid(다시 붙여넣으면 같은 접속으로 인식)를 읽는다. 여러 개를 한 번에 붙여넣어도 된다.
  - 지원: MySQL/MariaDB/Aurora, PostgreSQL, SQL Server(`;database=`, `\인스턴스`), Redis. 그 외 DB 는 "지원하지 않음"으로 알려준다.
  - 드라이버 래퍼 주소도 읽는다: `jdbc:aws-wrapper:mysql://`(AWS Advanced JDBC Wrapper), `jdbc:p6spy:`, `jdbc:log4jdbc:`, `jdbc:mysql:replication://`·`loadbalance://`(첫 호스트 사용), jTDS
  - 비밀번호는 DataGrip 이 따로 보관해서 들어 있지 않다 → 처음 연결할 때 입력.
  - SSH 터널을 쓰는 데이터 소스는 SSH 설정 id 만 들어 있다 → SSH 를 켠 상태로 가져오고 바스티온 정보는 접속 편집에서 넣으라고 안내.

## 25. Redis

- 접속 종류 **Redis** (기본 포트 6379). 비밀번호(AUTH), ACL 사용자(선택), DB 번호(0~15), TLS(ElastiCache 전송 중 암호화), SSH 터널, 읽기전용 지원.
- 드라이버: SwiftNIO 위에 RESP2 프로토콜을 직접 구현 (추가 라이브러리 없음). 명령은 파이프라인 순서대로 응답을 받는다.
- **사이드바**: DB 선택(키 개수 표시), 키 목록. `SCAN` 으로 1,000개씩 가져온다 (`KEYS` 는 운영 서버를 멈출 수 있어 쓰지 않음). 아래 검색칸에 패턴(`user:*`) + 타입 필터.
  - **트리 보기(기본)**: 키를 구분자(기본 `:`, `/` `.` `_` `-` `|` 선택)로 나눠 폴더처럼 표시 (`user:1001:name` → user › 1001 › name). 폴더마다 하위 키 개수, 숫자는 숫자 순서. 폴더 우클릭 "이 폴더만 검색". 트리/목록 전환 버튼.
  - 키마다 **타입 배지(S/H/L/St/Z/X)와 남은 TTL**(45s·12m·3h·2d, 1분 미만 주황)을 미리 표시 → 누르면 값이 열린다. 화면에 보이는 키만 TYPE·PTTL 을 파이프라인으로 묶어 조회.
  - 새로고침 + **자동 새로고침**(켜기/끄기, 간격 초 입력 1~3600, 기본 5초): 키 목록·TTL·열린 값을 다시 읽고 펼친 폴더와 선택은 유지. 연결이 끊기면 자동으로 멈춤.
- Redis 접속을 보고 있을 때는 **스키마 비교 비활성** (비교 대상 목록에도 Redis 제외).
- **키 탭**: 타입·TTL·원소 수·메모리(MEMORY USAGE)·인코딩 표시, 새로고침 / TTL 설정·해제 / 이름 변경 / 삭제(확인)
  - string: 편집 후 저장(`SET … KEEPTTL`), JSON 이면 보기 좋게 펼치기
  - hash: 필드·값 표, HSET / HDEL / list: LPUSH·RPUSH·LSET·LREM, 500개씩 더 보기 / set: SADD·SREM / zset: 점수 높은 순, ZADD·ZREM / stream: 최근 200개
  - 새 키 만들기 (타입별, 만료 지정)
- **Workbench**: 아래 여러 줄 편집기에 명령을 한 줄에 하나씩 쓰고 **▶ 실행(⌘↩)** → 위에서부터 차례로 실행, 결과는 위에 redis-cli 모양으로 쌓인다. 선택 영역이 있으면 그 줄만 실행. `//`·`#` 주석 줄은 건너뜀. 커서 줄 명령 인자 안내, 이전 명령 넣기, 결과에서 "편집기에 다시 넣기". 편집기 내용은 접속마다 기억. `FLUSHALL`·`FLUSHDB`·`KEYS`·`CONFIG SET`·`SHUTDOWN` 등이 섞여 있으면 실행 전에 한 번 더 확인. `SELECT` 하면 DB 표시도 바뀐다.
- **Pub/Sub**: 채널/패턴 구독(쉼표로 여러 개, `*`·`?` 가 있으면 PSUBSCRIBE), 들어오는 메시지 실시간 표 (시각·채널·패턴·메시지), 거르기·일시 정지·지우기, PUBLISH 보내기, 활성 채널과 구독자 수. 구독은 별도 연결을 쓴다.
- **Streams**: 스트림 목록 → 항목(최신순 200개씩, ID 시각 표시), `XADD`(`field=value …`), `XDEL`, **실시간 보기**(별도 연결에서 `XREAD BLOCK`), 소비자 그룹(소비자 수·대기·Lag·마지막 전달 ID), 그룹 만들기(`$`/`0`)·SETID 0·DESTROY, 소비자별 대기, PEL(ID·소비자·유휴·전달 횟수) → 선택해서 `XACK`.
- **서버 정보**: `INFO` 섹션별 표 + 주요 값(버전, 메모리, 클라이언트, 초당 명령 수 …), 찾기.
- 읽기전용 접속: 조회 명령만 허용 (GET/HGETALL/SCAN/XRANGE/XINFO/INFO/CONFIG GET … 허용 목록 방식). XREADGROUP·PUBLISH 도 막는다.
- 모든 쓰기 명령과 콘솔 명령은 상태창과 로그 파일에 남는다.
- **Redis Cluster**: 접속 편집 > 방식 "Cluster" (또는 "단일"로 붙어도 서버가 Cluster 면 자동 전환). 노드 하나(또는 ElastiCache 구성 엔드포인트)만 적으면 `CLUSTER SLOTS` 로 전체 노드·슬롯을 찾는다.
  - 명령은 키의 슬롯(CRC16, `{태그}` 지원)에 맞는 마스터로 보내고, `MOVED`(슬롯 표 다시 읽기)·`ASK`(ASKING 후 재전송) 는 자동으로 따라간다 → **노드 IP 로 다시 접속할 필요 없음**.
  - 키 목록(SCAN)·키 개수(DBSIZE)는 모든 마스터를 차례로 훑어 합친다. 타입·TTL 조회도 노드별로 묶어 파이프라인.
  - DB 는 0 만 (SELECT 는 안내). 서버 정보 탭에서 노드를 골라 노드별 INFO. Pub/Sub 은 아무 노드, Streams 실시간 보기는 키가 있는 노드.
  - SSH 바스티온을 쓰면 노드마다 터널을 자동으로 연다.
  - 상단에 "Cluster · 마스터 N개" 배지 (마우스를 올리면 노드 주소).
- **Redis Sentinel**: 방식 "Sentinel", 호스트 칸에 센티널 주소(쉼표로 여러 개, 기본 포트 26379), 마스터 이름(예: `mymaster`). `SENTINEL get-master-addr-by-name` 으로 현재 마스터를 찾아 접속 (센티널 인증이 필요하면 같은 비밀번호로 다시 시도). 장애 조치 후에는 다시 연결하면 새 마스터로 붙는다.
- 아직 안 되는 것: 복제본(replica) 읽기, RESP3, 모듈(JSON 등)은 Workbench 로만.

## 26. INSERT 컬럼 힌트

- `INSERT INTO t (a, b) VALUES ('x', 'y')` 처럼 쓰면 편집기에서 각 값 앞에 **회색으로 컬럼 이름**(`a`, `b`)이 보인다. 컬럼 목록을 안 쓰면 사이드바 스키마의 컬럼 순서로 표시.
- 여러 행(`VALUES (…), (…)`), 문자열 안 쉼표·괄호, 함수 호출, 주석, 입력 중(괄호가 안 닫힘)도 처리.
- 글자 사이 간격만 벌려 그 자리에 그리므로 **편집기 글자와 실행하는 SQL 은 바뀌지 않는다** (복사해도 글자만 복사).
- 설정 > 일반 > 편집기 > "INSERT 값 앞에 컬럼 이름 표시" 로 끌 수 있다.

## 27. 모델링

- 상단 모드에 **모델링** 추가 (쿼리 / 스키마 비교 / 모델링). 접속 없이도 쓸 수 있다.
- **논리 설계**: 논리명으로 테이블·컬럼을 만들고, 도구 막대의 관계 도구(1:N 비식별, 1:N 식별, 1:1)로 부모 → 자식 테이블을 차례로 누르면 관계가 생긴다. 부모 기본 키가 자식에 FK 컬럼으로 복사된다 (`id` 같은 흔한 이름은 `부모테이블_id`).
- **다이어그램**: IE 표기 (까마귀발 = N, 막대 = 1, 원 = 선택), 식별 관계는 실선 · 비식별은 점선. 카드 끌어 옮기기, 자동 정렬, 확대/축소, 카드 색, PNG 저장. 논리명 / 물리명 / 둘 다 보기.
- **물리 설계**: 아래 편집기에서 컬럼마다 논리명·물리명·타입(자주 쓰는 타입 메뉴)·PK·NN·AI·UQ·기본값·설명, 여러 컬럼 인덱스, 관계 속성(카디널리티, 식별, 선택, FK 이름, ON DELETE/UPDATE, FK 제약 생성 여부).
- **모델 검사**: 물리명 없음·중복·영문 외 글자, 타입 없음, 기본 키 없음. 오류가 있으면 SQL 추출을 막는다.
- **SQL 추출 (Forward Engineering)**: MySQL / PostgreSQL / SQL Server 문법으로 CREATE TABLE + FK(ALTER TABLE 로 마지막에). 코멘트는 `논리명` + 줄바꿈 + `설명`. DROP 먼저 옵션, 복사 · .sql 저장 · 쿼리 탭으로 열기 (실행은 직접).
- **리버스 엔지니어링**: 연결된 DB 의 테이블을 골라 모델로. 코멘트 첫 줄 → 논리명, FK → 관계, 원하면 컬럼 이름으로 추정한 관계(FK 제약 없는 논리 관계).
- **DB와 비교 (Synchronize)**: 모델과 연결된 DB 를 비교해 DB 를 모델에 맞추는 ALTER SQL (DB 에만 있는 것은 지우지 않음).
- **자동 정렬**: 도구 막대 격자 버튼. 관계를 따라 부모는 왼쪽 열, 자식은 오른쪽 열에 놓고 (같은 열은 부모 순서에 맞춰 선이 덜 엇갈리게), 관계 없는 테이블은 아래에 격자로. 카드 크기만큼 간격을 둬 겹치지 않는다. 되돌리기로 취소.
- 도구 막대 버튼마다 마우스를 올리면 하는 일을 한 줄로 알려 준다 (선택 · 테이블 추가 · 관계 도구 포함).
- **내보내기** 메뉴 (도구 막대 · 모델 목록 우클릭): 모델링 파일 저장하기(`.goddbmodel`) · 테이블 명세서로 저장하기 · 다이어그램 PNG 저장하기(도구 막대).
- **테이블 명세서(엑셀)**: 시스템명(기본: 모델 이름) · 작성자(기본: macOS 사용자 이름, 마지막 값 기억) · 작성일(기본: 오늘)을 물은 뒤 `<모델이름>_테이블명세서.xlsx` 로 저장.
  - **목차** 시트: 제목, DBMS · DB / 스키마 · 작성자 · 작성일, 테이블 목록(no · 테이블(그 시트로 가는 링크) · 테이블명 · 설명 · 컬럼 수). 모델의 테이블 순서.
  - **테이블마다 한 시트** (이름은 물리명, Excel 규칙에 맞게 31자 · 금지 문자 `_` · 겹치면 `~2`): 제목(물리명 · 논리명)과 "← 목차" 링크, 설명 · DBMS · 스키마, 그리고 세 구역
    - 컬럼: no · 컬럼 · 컬럼명 · 타입 · 길이(`varchar(50)` → `varchar` / `50`) · 키(PK / FK / PK, FK) · NN · 기본값(자동 증가는 AUTO_INCREMENT) · 설명 · 참조(`부모.컬럼`) · 비고(UQ)
    - 인덱스: 기본 키(SQL 추출과 같은 이름) → 유니크 · 일반 인덱스
    - 관계 (외래 키): 이 테이블이 자식인 관계의 이름 · `컬럼 → 부모.컬럼` · 카디널리티와 식별/비식별 · ON DELETE · ON UPDATE
    - 내용이 없는 구역은 "없음" 한 줄.
  - 맑은 고딕, 얇은 연한 테두리, 머리글 연한 파랑 채우기, 머리글 아래 틀 고정, A4 가로 · 너비 한 페이지 인쇄. 외부 라이브러리 없이 앱이 직접 만든다.
- 자동 저장, 되돌리기(구조 변경), 복제, 이름 바꾸기, `.goddbmodel` 파일 가져오기.

## 28. AI 어시스턴트 (오른쪽 패널)

- 도구 막대 ✨ 버튼 또는 ⇧⌘I. 로컬 Ollama (설정 > AI 의 모델) 와 대화.
- **쿼리 모드**: 테이블 목록 + 질문에 나온 테이블(물리명 또는 논리명) · 사이드바에서 고른 테이블 · 지금 탭 테이블의 구조·코멘트·인덱스·FK, 테이블 크기 통계(추정 행 수·용량), 자동 점검(기본 키 없음, 코멘트 없음, 인덱스 없는 FK, NULL 허용 FK, 중복 인덱스, 큰 테이블 등), 편집기 SQL·마지막 오류를 문맥으로 보낸다. 무엇을 보내는지 패널 위에 표시.
- **데이터 행은 보내지 않는다.** 데이터가 필요하면 실행할 SELECT 를 알려준다. 예외는 **데이터 찾기**(35절) 하나: 후보 컬럼의 값 몇 개(컬럼마다 최대 20개)를 **로컬 Ollama 에만** 보낸다. 이 PC 밖으로는 나가지 않는다.
- 이 DB 의 테이블 메모(최대 50개)를 "팀이 확인한 위치" 로 함께 보낸다.
- **앱 사용법 질문**: 앱 정보(제작자·라이선스·저장소)와 지금 앱 상태(버전·모드·연결·선택 테이블·열린 모델), 이 기능 명세에서 질문과 관련된 절을 함께 보내 "리버스 엔지니어링 어떻게 해?" 같은 질문에도 답한다. 접속하지 않아도 된다.
- **모델링 모드**: 지금 모델을 문맥으로 검토. "물리명 추천" 답의 JSON 을 **물리명 적용 (빈 칸만)** 버튼으로 모델에 바로 넣는다.
- 자주 쓰는 질문 버튼, 답의 SQL 을 편집기에 넣기, 범위(접속·DB / 모델)별 대화 기록 90일 보관 · 새 대화 · 삭제.

## 31. ID 로 찾기

로그에서 복사한 ID 여러 개를 붙여넣으면 `IN (…)` 으로 한 번에 조회하고, 결과에 없는 ID 를 알려 준다.

- **여는 곳**: 메뉴 데이터베이스 > **ID 로 찾기…** (⌥⌘F), 사이드바 테이블 우클릭 > **ID 로 찾기…** (그 테이블이 미리 선택됨). Redis 접속에서는 비활성.
- **창**: 테이블 · 컬럼(`이름 (타입)`) 선택, 붙여넣기 칸, `찾은 값 N개 (중복 M개 제외) : …` 미리보기 (앞 20개 + "…외 N개"), **문자 ID 포함** 체크, [취소] [조회 (⌘↩)]. 값이 없으면 [조회] 비활성.
- **기본값**: 테이블은 사이드바에서 고른 테이블 → 이 기능에서 마지막으로 쓴 테이블 → 빈칸. 컬럼은 이 테이블에서 마지막으로 쓴 컬럼 → 기본 키(단일 컬럼) → 첫 컬럼. 마지막 선택은 접속 · DB 별로 `id-search.json` 에 기억.
- **값 뽑기**: 숫자 컬럼은 단어에 붙지 않은 숫자만(`memberNo=1023` → 1023, `user42` · `A-77` · `v1.2` 는 제외), 문자 컬럼이나 "문자 ID 포함" 이면 영문 · 숫자 · `_-:.` 로 된 토큰(UUID 포함). 날짜 · 시각(`2026-11-20`, `10:01:02.123`, ISO 8601)과 로그 레벨 단어(INFO · WARN · ERROR · DEBUG · TRACE)는 뺀다. 순서를 지키며 중복 제거, 최대 1,000개 (넘으면 "1,000개까지만 조회해요" 안내).
- **실행**: 새 쿼리 탭 `ID: <테이블>.<컬럼> (N)` 에서 `SELECT * FROM <테이블> WHERE <컬럼> IN (…)`. 이름은 DB 별 인용, 숫자 컬럼은 따옴표 없이, 문자는 DB 별 문자열 인용 (SQL Server 는 `N'…'`). 행 수 제한은 평소 설정을 쓰되 값이 더 많으면 값 개수 이상으로 올린다 (최대 5,000). 기존 조회처럼 감사 로그 · 히스토리에 남는다.
- **없는 ID**: 결과가 끝까지 들어온 경우(더 있음 아님)에만 결과 아래에 `요청 N · 찾음 N · 없음 N [없는 ID 복사]` (한 줄에 하나씩 복사). 비교는 문자열로, 대소문자 구분 없이, 숫자는 앞 0 을 떼고.

## 32. 저장 쿼리

자주 쓰는 쿼리를 이름 · 폴더로 저장해 두고, `:이름` 빈칸을 채워 실행한다.

- **저장**: 메뉴 데이터베이스 > **쿼리 저장…** (⌥⌘S). 선택 영역 → 커서가 있는 문장 → 편집기 전체 순으로 저장할 SQL 을 고른다. 창: 이름(필수, 기본값 = 첫 줄 앞 40자), 폴더(선택, 있는 폴더 자동완성), 보이는 곳 `모든 접속`(기본) / `이 접속만`, 찾은 빈칸 `빈칸: :a, :b`.
- **목록**: 메뉴 데이터베이스 > **저장 쿼리…** (⇧⌘K), 쿼리 도구 막대 **저장 쿼리** (🔖), ⌘O 빠른 찾기의 `저장 쿼리` 종류. 검색(이름 · SQL · 폴더), 폴더별 묶음, 최근 사용 순. `이 접속만` 은 그 접속을 보고 있을 때만 보인다. Redis 접속에서는 비활성.
- **우클릭**: 실행 · 편집기에 넣기 · 이름 바꾸기 · 폴더 바꾸기 · 복제 · 삭제(확인).
- **빈칸 규칙**: `:이름` (이름은 `[A-Za-z_][A-Za-z0-9_]*`). 문자열(`'…'` `"…"` `` `…` ``) · 주석(`--`, `/* */`, MySQL 의 `#`) · PostgreSQL `$$ … $$` 안과 `::type` 캐스트 · `:=` 는 빈칸이 아니다. 같은 이름은 한 번만 묻는다.
- **실행**: 목록에서 더블클릭 또는 ↩. 빈칸이 없으면 바로, 있으면 입력 창 (`:이름 [값] [ ] NULL [ ] 그대로 넣기`, 채운 SQL 미리보기, [넣기만] [취소] [실행 (⌘↩)]).
  - 값 변환: 숫자 꼴(`-12`, `3.5`)은 그대로, 그 밖은 DB 별 문자열 인용 (SQL Server 는 `N'…'`). NULL 체크면 `NULL`, **그대로 넣기** 면 입력을 SQL 조각으로 그대로(`NOW()` 등).
  - 쉼표가 있으면 목록으로 펼친다: `IN (:ids)` 에 `1,2,3` → `IN (1, 2, 3)`, `kim,lee` → `'kim', 'lee'`.
  - 마지막 입력값을 쿼리별로 기억해 다음에 채워 둔다.
  - [실행] = 지금 탭이 비었으면 그 탭, 아니면 새 탭(제목 = 저장 쿼리 이름)에 넣고 평소처럼 실행 (위험 문장 · 운영 접속 확인, 감사 로그 · 히스토리 그대로). [넣기만] = 넣고 실행하지 않음.

## 33. 외래 키 따라가기

결과 행의 외래 키 값으로 참조하는 행을, 또는 이 행을 참조하는 행을 새 탭에서 바로 조회한다.

- **관계**: 스키마를 읽을 때 함께 읽은 외래 키 (읽지 못하면 없이 진행) + **추정 관계** (ER 다이어그램과 같은 규칙: 컬럼 이름이 다른 테이블의 단일 기본 키 이름과 같고(대소문자 무시) 그 테이블이 하나뿐일 때, `id` · `seq` · `no` 같은 흔한 이름은 제외). 추정 관계는 메뉴에 `· 추정`, 머리글 ↗ 를 흐리게 표시.
- **어디서**: 결과가 **테이블 하나에서 온 조회**일 때만 (결과 편집과 같은 판단). 조인 · 집계 · UNION · 서브쿼리 결과에는 나오지 않는다. 결과 편집과 달리 읽기전용 접속 · 기본 키 없는 결과에서도 따라가기는 된다.
  - 결과 표 머리글: 외래 키 컬럼 이름 옆 ↗ (추정이면 흐린 ↗).
  - 외래 키 칸 **⌘ 클릭** 또는 우클릭 > **참조 따라가기 → `<테이블>` (<컬럼>)**. 값이 NULL 이면 비활성. ⌘ 클릭 여러 행 선택은 외래 키가 아닌 칸에서 그대로 된다.
  - 우클릭 > **이 행을 참조하는 행 ▸** — 이 테이블을 참조하는 테이블 목록 (`tb_order (member_no)`). 기본 키가 단일 컬럼이고 결과에 그 값이 있을 때만.
  - 행 상세: 외래 키 칸 이름 옆 ↗ 버튼, 맨 아래 **참조하는 테이블** 버튼 목록.
- **실행**: 따라가기는 새 탭 `↗ <테이블>` 에서 `SELECT * FROM <참조 테이블> WHERE <참조 컬럼> = <값>` (복합 키는 `AND` 로 모두), 참조하는 행은 새 탭 `↙ <테이블>` 에서 `SELECT * FROM <참조하는 테이블> WHERE <FK 컬럼> = <이 행 기본 키 값>`. 값 인용은 ID 로 찾기와 같다 (숫자 컬럼은 그대로, 그 밖은 DB 별 문자열 인용, SQL Server 는 `N'…'`). 평소 실행 경로라 감사 로그 · 히스토리 · 안전 확인이 그대로 적용된다.

## 34. JSON 보기

JSON 이 든 칸을 행 상세에서 원문 · 정렬 · 트리로 본다.

- **판단**: 값의 앞뒤 공백을 뺀 뒤 `{` 또는 `[` 로 시작하고 JSON 으로 파싱되면 JSON 칸. 컬럼 타입이 `json` · `jsonb` 이면 (한 테이블 조회라 타입을 알 때) 시작 글자는 보지 않고 파싱만 확인한다. 1MB 가 넘으면 파싱하지 않고 "너무 커서 원문만 보여요" + 원문.
- **행 상세**: JSON 칸 위에 보기 전환 **원문 · 정렬 · 트리**. 마지막 선택을 기억 (`GodDB.json.viewMode` = `raw` · `pretty` · `tree`, 기본 트리).
  - 정렬: 들여쓰기 2칸, 키는 받은 순서 그대로 (MySQL 은 JSON 타입 값을 저장할 때 키를 길이 → 글자 순으로 바꿔 돌려준다), 고정폭 글꼴, 선택 가능. 한글 · 이모지는 그대로, 따옴표 · 역슬래시 · 제어 문자만 이스케이프.
  - 트리: 처음엔 2단계까지 펼침, 객체 · 배열 줄을 누르면 펼치기/접기 (`{…} 3` 처럼 항목 수 표시). 값 종류별 색 (문자 · 숫자 · 참거짓 · null). 숫자는 받은 글자 그대로 (정밀도 손실 없음).
  - 항목 우클릭 > **값 복사** (문자는 따옴표 없이 내용만, 객체 · 배열은 정렬한 JSON) · **경로 복사** (`$.order.items[0].sku`, 식별자가 아닌 키는 `$["key with space"]`).
- **결과 표**: JSON 칸은 그대로 원문 한 줄 (변경 없음).
- **편집**: 원문 편집만 — 정렬 · 트리는 고친 값을 보여 주기만 하고, 고치려면 원문으로 바꾼다. JSON 칸(타입이 `json` · `jsonb` 이거나 원래 값이 JSON)의 값이 JSON 이 아니게 되면 칸 아래와 적용 확인 창에 "JSON 형식이 아니에요" 경고. 저장(적용)은 그대로 할 수 있다.

## 35. AI 데이터 찾기 + 테이블 메모

"학년 정보는 어디 있어?" 처럼 물으면 그 데이터가 든 테이블 · 컬럼을 찾아 실제 값으로 확인하고, 찾은 위치는 테이블 메모로 기억해 다음에는 AI 없이 바로 답한다.

- **여는 곳**: AI 어시스턴트의 빠른 동작 **🔎 데이터 위치 찾기** (입력이 "데이터 찾기" 모드로). 입력이 `…(은|는|이|가) 어디(에|서) 있/저장/들어…`, `…어디야`, `…어딨어`, `where is …`, `which table …` 꼴이면 자동으로 데이터 찾기 (SQL · 오류 · 성능 · 크기를 묻는 말이 섞이는 등 애매하면 일반 질문). SQL 접속에서만 — Redis · 모델링에서는 버튼이 없다.
- **핵심어**: 질문에서 조사 · "정보 · 데이터 · 어디 · 있어" 같은 말을 뺀 명사 ("학년 정보는 어딨어?" → `학년`). 비교는 공백 제거 · 소문자 (한글 그대로).
- **처리 순서**:
  1. **메모 먼저**: 이 접속 · DB 의 메모 찾는 말과 맞으면 바로 답 카드 (AI 호출 없음, 카드에 [다시 찾기]).
  2. **후보 고르기 (로컬 AI 1차)**: 질문, 테이블 `이름 — 코멘트`, 컬럼 `이름 타입 — 코멘트` (약 2만 자 예산을 넘으면 이름 · 코멘트가 핵심어와 겹치는 테이블 먼저), 기존 메모를 보내고 `{"candidates":[…]}` (최대 5개) 를 받는다. 형식이 틀리면 한 번 더 묻고, 그래도 안 되면 이름 · 코멘트 키워드 일치 순. 없는 테이블 · 컬럼은 버린다.
  3. **샘플 조회 (앱이 직접)**: 후보 컬럼마다 `SELECT <col> FROM <table> WHERE <col> IS NOT NULL LIMIT 200` (SQL Server `TOP 200`). 중복 빼고 최대 20개, 값은 50자로 자름, 쿼리마다 5초 제한 (넘으면 "샘플 없음"). 읽기전용 접속도 된다. **운영 접속**이면 접속마다 처음 한 번 묻는다: [이번만] [이 접속은 항상] (앱을 켜 둔 동안) [취소].
  4. **판단 (로컬 AI 2차)**: 질문 + 후보 + 샘플 값 → `{"table","columns","confidence","explain","sql"}`. `sql` 은 SELECT 하나만 (아니면 `SELECT * FROM <table>`). 형식이 틀리면 첫 후보 (신뢰도 낮음).
- **답 카드**: 제목, `테이블.컬럼`, 신뢰도 (높음 · 중간 · 낮음), `AI · 미확인` / `확인됨`, 값 예, 설명, 다른 후보, 보낸 내용 칩 `테이블 목록 N개` `후보 컬럼 샘플 M개 (로컬)`.
  - [데이터 보기]: 새 탭에서 평소 실행 경로로 (LIMIT · 감사 로그 · 히스토리). [SQL 넣기]: 같은 접속의 지금 탭(없으면 새 탭)에.
  - [맞아요]: 메모를 확인됨으로. [아니에요]: 메모를 지우고 다음 후보 (없으면 "다른 후보가 없어요").
  - 대화 기록에는 카드 대신 한 줄 요약이 남는다.
- **테이블 메모**: 답 카드가 나오면 자동 저장 (`source: ai`, 미확인). 같은 테이블 + 컬럼 메모가 있으면 찾는 말만 합친다. 사이드바 테이블 이름 옆 📝 (누르면 메모 창), 우클릭 > **테이블 메모…** → 그 테이블의 메모: 찾는 말(쉼표), 컬럼, 설명, 확인됨 체크, 삭제, [메모 추가] (직접 추가는 확인됨). 저장은 `table-notes.json`.
- **보내는 것 · 기록**: AI 는 설정 > AI 의 로컬 Ollama(이 PC 만)로만. 샘플 값은 데이터 찾기에서만 보내고 저장하지 않는다. 감사 로그 `AI | 접속/DB | 데이터 찾기 · 후보 N · 샘플 조회 M` (질문 · 값은 남기지 않음), 샘플 조회 SQL 은 평소처럼 `조회` 줄.

## 36. TLS 서버 인증서 확인

MySQL · PostgreSQL · Redis 의 TLS 연결에서 서버 인증서를 확인한다. 접속 편집 **TLS 사용** 아래 **서버 인증서 확인** (기본 켬, 예전 접속도 켬으로 읽는다).

- **직접 접속(SSH 없이)**: 서버가 보낸 인증서 체인을 macOS 시스템 신뢰 저장소(Security.framework, `SecPolicyCreateSSL` + 호스트 이름)로 확인 → 통과하면 묻지 않고 연결.
  - 실패하면(사설 · 자체 서명 인증서, IP 로 접속, 이름 불일치, 만료) 확인 창: 주체(CN) · 발급자 · 유효 기간 · **SHA-256 지문**(`3F:A2:…`) · 이유(신뢰할 수 없는 발급자 / 이름이 다름 / 만료됨) · [취소] [이 인증서 신뢰 (고정)].
  - 신뢰하면 맨 앞(서버) 인증서 DER 의 SHA-256 을 접속 정보 `tlsPinSHA256` 에 저장하고 다시 연결. 다음부터 체인 확인이 실패해도 **지문이 같으면 연결**.
  - 지문이 바뀌면(체인이 통과해도) 연결하지 않고 "서버 인증서가 바뀌었어요 …" + [저장된 인증서 지우기]. 지우면 다시 연결해 새 인증서를 확인 창으로 보여 준다.
- **SSH 터널 경유**: 터널 안쪽은 `127.0.0.1` 이라 이름 · 체인은 확인하지 않는다 (서버 확인은 SSH 호스트 키가 맡는다). 고정 지문이 있으면 지문만 확인.
- **Redis Cluster · Sentinel**: 노드마다 같은 규칙. 서버가 알려 준 노드 주소가 IP 면 이름 확인에는 접속 정보의 호스트 이름을 쓴다. 고정 지문은 하나라 노드마다 인증서가 다르면 고정으로는 쓸 수 없다 (공인 인증서면 문제없음).
- **TLS 필수**: TLS 를 켜면 서버가 TLS 를 안 할 때 평문으로 내려가지 않고 "서버가 TLS 를 지원하지 않아요. TLS 를 끄거나 SSH 터널을 쓰세요." (PostgreSQL `sslmode=require` 와 같음, MySQL 도 같게).
- **SQL Server**: FreeTDS(DB-Library) 는 인증서 · 지문 확인을 할 수 없어 암호화만 강제한다. 접속 편집에 "SQL Server 는 암호화만 하고 서버 인증서는 확인하지 못해요. 외부망에서는 SSH 터널이나 VPN 을 쓰세요."
- **서버 인증서 확인을 끄면** 예전처럼 암호화만 한다 (접속 편집에 경고).
- **상태창**: 연결 후 한 줄 `TLS 사용 · 인증서 확인됨` / `TLS 사용 · 고정 인증서` / `TLS 사용 · 확인 안 함(SSH 터널)` / `TLS 사용 · 확인 안 함` / `TLS 사용 · 암호화만(인증서 확인 불가)`(SQL Server) / `TLS 안 씀`. 접속 편집의 연결 테스트 결과에도 붙는다.
- **접속 편집**: 고정한 인증서 지문과 [저장된 인증서 지우기]. 연결 테스트에서 확인 창이 뜨면 신뢰한 지문은 편집 중인 접속에 들어가고 저장할 때 반영된다.
- **감사 로그**: `설정 | ‹접속› | TLS 인증서 신뢰 SHA256:…` / `설정 | ‹접속› | 인증서 고정 지움`.
- 구현: NIOSSL 사용자 정의 확인 콜백 (`Vendor/mysql-nio` · `Vendor/postgres-nio` 패치로 콜백을 넘긴다 — 각 `GODDB_PATCH.md`).

## 37. SSH 호스트 키 확인

SSH 터널의 바스티온 서버 키를 처음 접속할 때 확인받는다 (예전에는 `accept-new` 로 묻지 않고 저장).

- **연결 전**: `ssh -G` 로 `~/.ssh/config` 의 HostName · Port · HostKeyAlias 를 반영한 이름(`host` 또는 `[host]:port`)을 `ssh-keygen -F` 로 `~/.ssh/known_hosts` 와 GodDB 전용 `~/Library/Application Support/GodDB/known_hosts` 에서 찾는다.
- **없으면**: `ssh-keyscan -T 5 -p <port> <host>` 로 키를 받고 `ssh-keygen -lf -` 로 지문(SHA256) 계산 → 확인 창 "처음 접속하는 SSH 서버예요 — host:port", 키 종류 · 지문, "서버 관리자에게 받은 지문과 같은지 확인하세요." [취소] [신뢰하고 연결].
  - 신뢰하면 받은 키를 GodDB 전용 `known_hosts`(권한 0600)에 더하고 다시 연결. `~/.ssh/known_hosts` 는 건드리지 않는다.
- **ssh 실행**: `-o StrictHostKeyChecking=yes -o UserKnownHostsFile="~/.ssh/known_hosts" "<GodDB known_hosts>"` (경로의 공백 때문에 큰따옴표).
- **키가 바뀌면** ssh 가 거부 (`REMOTE HOST IDENTIFICATION HAS CHANGED`) → "SSH 서버 키가 바뀌었어요 …" + [저장된 키 지우기] — `ssh-keygen -R` 로 **GodDB 전용 파일에서만** 지우고 다시 연결(처음 접속 확인). `~/.ssh/known_hosts` 의 키는 직접 지워야 한다고 안내.
- **감사 로그**: `설정 | SSH 호스트 키 신뢰 host:port SHA256:…` / `설정 | SSH 호스트 키 지움 host:port`.

- **설치 흐름** ([설치…]):
  1. 확인 창 "1.3.6 으로 되돌릴까요? 앱을 끄고 이전 버전을 설치한 뒤 다시 켭니다. …" + **이 버전에 머물기 (자동 업데이트를 '수동'으로 바꿈)** (기본 체크 — 체크하면 설치 직전에 설정 > 업데이트를 수동으로).
  2. 커밋하지 않은 트랜잭션이 있으면 앱 종료와 같은 확인 창 ([롤백하고 설치] [취소]).
  3. 데이터 폴더 `…/GodDB` 를 옆에 `GodDB-backup-<지금 버전>-<YYYYMMDD-HHmmss>` 로 복사. 백업은 최근 3개만 남긴다.
  4. `GodDB-<버전>.dmg` 를 임시 폴더로 내려받기 (진행률, [취소]).
  5. 검증 — 하나라도 실패하면 설치하지 않고 이유를 보여 준다: DMG 를 `hdiutil attach -nobrowse -readonly` 로 열고 → `codesign --verify --deep --strict` → 서명 팀 ID 가 지금 앱과 같음 (`codesign -dv` 의 `TeamIdentifier`, 지금 앱은 `SecCodeCopySigningInformation`) → 번들 ID 같음 → `spctl --assess --type execute`(공증) → 최소 macOS · 버전 확인.
     - 지금 앱이 서명 없는 개발 빌드(`swift run` · ad-hoc)면 비교할 팀 ID 가 없어 설치를 거부한다.
     - 앱 위치에 쓸 수 없으면(App Translocation 등) 시작 전에 거부.
  6. 교체: 임시 폴더에 `/bin/sh` 도우미 스크립트를 쓰고 띄운 뒤 앱 종료. 도우미는 앱이 끝나기를 기다렸다가(최대 60초) 새 앱을 `<앱>.goddb-new-…` 로 `ditto` → 격리 속성 제거 → 원래 앱을 옆으로 옮기고 새 앱을 제자리로 → 원래 앱 삭제 → DMG 닫기 → 다시 실행. 경로는 작은따옴표로 인용 (공백 · 따옴표 · 한글 경로).
     - 실패하면 원래 앱을 제자리에 두고 `previous-version-install-failed.txt` 에 이유를 남기고 원래 앱을 다시 연다. 다음 실행 때 "이전 버전을 설치하지 못했어요" 창 + 상태창 오류로 알리고 표시 파일을 지운다.
  7. 감사 로그 `설정 | 이전 버전 설치 1.4.0 → 1.3.6`.

## 17. 알려진 제약

- SQL Server: 세션 단위 읽기전용이 없어 앱 검사만 한다 (서버에서 강제되지 않음). 운영 DB 는 **읽기 권한만 있는 DB 계정**을 쓴다. 접속 편집에서 읽기전용을 켜면 같은 안내가 나온다. 기본값 변경 시 기존 기본값 제약조건 삭제는 안내 주석으로만 만든다. Windows 통합 인증 미지원 (SQL 인증만).
- SQL Server 드라이버(FreeTDS)는 빌드할 때만 Homebrew 가 필요하다. 배포 앱에는 라이브러리가 들어 있다.
- 서로 다른 종류의 DB 끼리 스키마 비교는 가능하지만 타입 이름 차이로 "다름"이 많이 나온다.
- 비밀번호 방식 SSH 미지원.
- SQL Server TLS 는 암호화만 한다 (FreeTDS 로는 서버 인증서 · 지문 확인 불가). 외부망에서는 SSH 터널이나 VPN.
- SSH 바스티온이 `ProxyJump` 를 거쳐야 하면 `ssh-keyscan` 이 키를 받지 못한다 → 터미널에서 한 번 접속해 `~/.ssh/known_hosts` 에 키를 넣어 두면 그 키를 쓴다.
- 화면 자동 테스트(`scripts/ui-test.sh`)는 MySQL 화면 흐름만 확인한다. PostgreSQL · SQL Server · Redis 화면은 수동 확인.
