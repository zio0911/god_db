# GodDB 1.4.0 기능 명세 (Mac · Windows 공통)

> 상태: **검토 중 (구현 전)** · 작성 2026-11-20 · 기준 Mac 1.3.7
> 이 문서는 Mac 판과 Windows 판이 **같은 동작 · 같은 저장 형식**으로 구현하기 위한 명세다. 화면 배치는 플랫폼에 맞게 달라도 되지만, 동작 · 문구 · 파일 형식 · SQL 은 같게 한다.
> 단축키 표기는 Mac 기준이고, Windows 는 ⌘ → Ctrl, ⌥ → Alt 로 바꾼다.

## 0. 목표와 범위

실제 사용 방식은 **로그를 보고 판단 → DB 에서는 일부 데이터를 확인**하는 것이다. 1.4.0 은 이 흐름을 빠르게 하는 데 집중한다.

| # | 기능 | 한 줄 |
|---|---|---|
| F1 | ID 로 찾기 | 로그에서 복사한 ID 여러 개를 붙여넣으면 `IN (…)` 조회 + 없는 ID 표시 |
| F2 | 저장 쿼리 | 자주 쓰는 확인 쿼리를 저장, `:이름` 빈칸만 채워 실행 |
| F3 | 외래 키 따라가기 | 결과 셀에서 참조하는 행 / 참조받는 행으로 바로 이동 |
| F4 | JSON 보기 | JSON 이 든 칸을 행 상세에서 트리 · 정렬해서 |
| F5 | 이전 버전 설치 | 릴리스 목록에서 골라 이전 버전으로 되돌리기 |
| F6 | 운영 접속 자동 끊기 | 운영 접속을 30분 안 쓰면 자동으로 끊기 |
| F7 | AI 데이터 찾기 + 테이블 메모 | "학년 정보는 어디 있어?" → 위치를 찾아 주고, 찾은 위치는 테이블 메모로 기억 |
| F8 | 쿼리 튜닝 제거 | AI 쿼리 튜닝 기능을 모두 뺀다 (실행 계획은 유지) |
| F9 | 보안 강화 | Ollama 는 이 PC 만, TLS 서버 인증서 확인 + 고정, SSH 호스트 키 확인, SQL Server 읽기전용 안내 |

제외: 개발 ↔ 운영 데이터 비교, 감사 로그 끄기 제한 (나중에 결정).

### 공통 원칙

- **데이터는 이 PC 밖으로 나가지 않는다.** 클라우드 AI 사용 없음. F7 의 샘플 값은 **로컬 Ollama 에만** 보낸다 (2026-11-20 결정).
- 새로 실행하는 SQL 은 모두 **조회(SELECT)** 이고, 기존 실행 경로(LIMIT 자동 부여 · 페이지 · 감사 로그)를 그대로 탄다.
- 운영 접속(`environment = production`)에서도 조회는 확인 없이 실행한다 (기존과 같음). 단 F7 의 샘플 조회는 운영 접속에서 **접속마다 처음 한 번** 묻는다.
- 새 문구는 한국어 · 영어 모두 넣는다 (번역 누락 테스트 통과).
- 감사 로그 구분은 기존 값만 쓴다 (`조회`, `설정`, `AI`, `접속해제` 등).

## F1. ID 로 찾기

### 들어가는 곳
- 메뉴 **데이터베이스 > ID 로 찾기…** (⌥⌘F)
- 사이드바 테이블 우클릭 > **ID 로 찾기…** (그 테이블이 미리 선택됨)
- Redis 접속이면 메뉴 비활성.

### 창 구성 (시트 / 대화상자)
```
┌ ID 로 찾기 ─────────────────────────────────────┐
│ 테이블 [tb_member        ▾]  컬럼 [member_no ▾] │
│ ┌ 붙여넣기 ─────────────────────────────────┐ │
│ │ 2026-11-20 10:01:02 ERROR memberNo=1023 …  │ │
│ │ memberNo=2044, orderId=A-77 …              │ │
│ └────────────────────────────────────────────┘ │
│ 찾은 값 3개 (중복 1개 제외) : 1023, 2044, 77    │
│ [ ] 문자 ID 포함 (영문 · 하이픈)                 │
│                         [취소]  [조회 (⌘↩)]     │
└──────────────────────────────────────────────────┘
```
- **테이블 기본값**: 사이드바에서 고른 테이블 → 없으면 이 기능에서 마지막으로 쓴 테이블 → 없으면 빈칸.
- **컬럼 기본값**: 이 테이블에서 마지막으로 쓴 컬럼 → 없으면 기본 키(단일 컬럼일 때) → 없으면 첫 컬럼. 컬럼 목록은 `이름 (타입)` 으로.
- 마지막 선택은 접속 · DB 별로 기억 (`~/…/GodDB/id-search.json`, §저장 형식).

### 값 뽑기 규칙
1. 붙여넣은 글을 다음 정규식으로 토큰화한다.
   - 숫자 컬럼(정수 · 소수 타입): `(?<![\w.-])-?\d+(?![\w.])` → 숫자만.
   - 문자 컬럼 또는 "문자 ID 포함" 체크: `[A-Za-z0-9][A-Za-z0-9_\-:.]{0,99}` (UUID 포함). 단 날짜 · 시각 꼴(`\d{4}-\d{2}-\d{2}`, `\d{2}:\d{2}:\d{2}`)과 로그 레벨 단어(`INFO|WARN|WARNING|ERROR|DEBUG|TRACE`)는 뺀다.
2. 앞에서부터 순서를 지키며 중복 제거.
3. 최대 **1,000개**. 넘으면 앞 1,000개만 쓰고 "1,000개까지만 조회해요 (나머지 N개는 다시 붙여넣으세요)" 표시.
4. 값이 0개면 [조회] 비활성.
5. 찾은 값 미리보기는 앞 20개 + "…외 N개".

### 실행하는 SQL
```sql
SELECT * FROM <테이블> WHERE <컬럼> IN (<값1>, <값2>, …)
```
- 테이블 · 컬럼 이름은 다이얼렉트 인용(`quoteTable`, `quoteIdent`).
- 숫자 컬럼은 따옴표 없이, 그 밖은 `quoteString` (MSSQL 은 `N'…'`).
- 새 쿼리 탭(제목 `ID: <테이블>.<컬럼> (N)`)에 SQL 을 넣고 실행. 결과 행 수 제한은 평소 설정 그대로 (100 · 500 …). 1,000개 IN 이면 제한을 **값 개수 이상**으로 자동으로 올린다 (최대 5,000).

### 없는 ID 표시
- 결과가 끝까지 들어온 경우(`hasMore = false`)에만, 결과의 그 컬럼 값과 비교해 **없는 값**을 결과 아래 줄에 표시:
  `요청 120 · 찾음 117 · 없음 3 [없는 ID 복사]`
- 비교는 문자열로 (숫자는 앞 0 제거 후 비교, 대소문자 구분은 DB 와 무관하게 구분 안 함).
- 결과가 잘렸으면 표시하지 않는다.

### 확인 기준
- 로그 3줄을 붙여넣으면 숫자 ID 만 순서대로 중복 없이 뽑힌다.
- MySQL · PostgreSQL · SQL Server 각각 숫자 · 문자 컬럼으로 조회가 된다.
- 없는 ID 가 정확히 표시되고 복사된다.

## F2. 저장 쿼리

### 들어가는 곳
- 편집기에서 **쿼리 저장…** (⌥⌘S): 선택 영역 또는 커서 문장(없으면 전체)을 저장.
- **저장 쿼리 목록** (⇧⌘K): 도구 막대 🔖 버튼 · 메뉴 데이터베이스 > 저장 쿼리….
- ⌘O 빠른 찾기 결과에도 `저장 쿼리` 종류로 나온다.

### 저장 창
- 이름(필수, 기본값: 첫 줄 앞 40자), 폴더(선택, 자유 입력 · 기존 폴더 자동완성), 범위: `모든 접속` / `이 접속만`(기본: 모든 접속).
- 찾은 빈칸 목록을 보여 준다: "빈칸: :memberNo, :from".

### 빈칸(파라미터) 규칙
- `:이름` — 이름은 `[A-Za-z_][A-Za-z0-9_]*`.
- 다음 안에 있는 `:` 는 빈칸이 아니다: 문자열 리터럴(`'…'`, `"…"`, `` `…` ``), 주석(`--`, `#`(MySQL), `/* */`), PostgreSQL 캐스트 `::type`, `:=`.
- 같은 이름이 여러 번 나오면 입력은 한 번.

### 실행 흐름
1. 목록에서 더블클릭(또는 ↩) → 빈칸이 없으면 바로 새 탭에 넣고 실행.
2. 빈칸이 있으면 입력 창:
   ```
   :memberNo [ 1023          ]  [ ] NULL  [ ] 그대로 넣기
   :from     [ 2026-11-01    ]  [ ] NULL  [ ] 그대로 넣기
   [넣기만]                         [취소]  [실행 (⌘↩)]
   ```
   - 값 변환: 숫자 꼴(`^-?\d+(\.\d+)?$`)은 그대로, 그 밖은 `quoteString`. NULL 체크면 `NULL`. "그대로 넣기"면 입력을 SQL 조각으로 그대로(예: `NOW()`, `1,2,3`).
   - 값에 쉼표가 있고 "그대로 넣기"가 아니면 **목록으로 펼친다**: `1,2,3` → `1, 2, 3` (각각 변환). `IN (:ids)` 용.
   - 마지막 입력값을 쿼리별로 기억해 다음에 채워 둔다.
3. [실행] = 지금 탭이 비었으면 그 탭, 아니면 새 탭(제목 = 저장 쿼리 이름)에 넣고 실행. [넣기만] = 넣고 실행하지 않음.

### 목록 창
- 검색(이름 · SQL · 폴더), 폴더별 묶음, 정렬: 최근 사용 순.
- 우클릭: 실행 · 편집기에 넣기 · 이름 바꾸기 · 폴더 바꾸기 · 복제 · 삭제(확인).
- `이 접속만` 범위는 그 접속을 보고 있을 때만 보인다.

### 확인 기준
- `WHERE a = :x AND b::text = ':y' -- :z` 에서 빈칸은 `:x` 하나.
- `IN (:ids)` 에 `1,2,3` → `IN (1, 2, 3)`.
- 앱을 다시 켜도 저장 쿼리와 마지막 입력값이 남는다. Mac 에서 만든 파일을 Windows 판이 그대로 읽는다.

## F3. 외래 키 따라가기

### 외래 키 정보
- 스키마를 읽을 때(테이블 목록 새로고침) 외래 키도 함께 읽는다 (`foreignKeysSQL`, 지금은 ER 다이어그램에서만 읽음). 실패하면 없이 진행.
- **추정 관계**: 실제 외래 키가 없어도, 컬럼 이름이 다른 테이블의 단일 기본 키 이름과 같고(대소문자 무시) 그 테이블이 하나뿐이면 추정 관계로 본다 (ER 다이어그램과 같은 규칙 `inferredRelations`). 화면에 "추정" 표시.

### 결과의 원본 테이블
- 결과가 **한 테이블에서 온 조회**일 때만 동작 (결과 편집 기능의 원본 판단 `EditTarget` 과 같은 규칙). 조인 · 집계 결과에서는 메뉴가 나오지 않는다.

### 화면
- 결과 표에서 외래 키 컬럼 머리글 옆에 ↗ 아이콘 (추정이면 흐린 ↗).
- 셀 **⌘ 클릭**(Windows: Ctrl 클릭) 또는 우클릭 > **참조 따라가기 → `tb_member` (member_no)**.
- 우클릭 > **이 행을 참조하는 행 ▸** — 이 테이블을 참조하는 테이블 목록(예: `tb_order (member_no)`). 기본 키가 단일 컬럼이고 그 값이 있을 때만.
- 행 상세: 외래 키 칸 값 옆 ↗ 버튼, 맨 아래 "참조하는 테이블" 버튼 목록.

### 실행하는 SQL
- 따라가기: `SELECT * FROM <참조 테이블> WHERE <참조 컬럼> = <값>` (복합 키는 `AND` 로 모두). 값이 NULL 이면 비활성.
- 참조하는 행: `SELECT * FROM <참조하는 테이블> WHERE <그 테이블의 FK 컬럼> = <이 행 기본 키 값>`.
- 값 인용은 컬럼 타입 기준 (F1 과 같음).
- 새 탭(제목 `↗ <테이블>` / `↙ <테이블>`)에 넣고 실행.

### 확인 기준
- 테스트 DB 에 `ui_customers(id PK)`, `ui_orders.customer_id → ui_customers.id` 외래 키를 만들고 따라가기 · 참조하는 행 모두 동작.
- 외래 키가 없는 `customer_no` 같은 컬럼은 추정 관계로 동작.
- 조인 결과에서는 메뉴가 없다.

## F4. JSON 보기

### 판단
- 값을 앞뒤 공백을 뺀 뒤 `{` 또는 `[` 로 시작하고 JSON 으로 파싱되면 JSON 칸. (컬럼 타입 `json` / `jsonb` 는 파싱만 확인)
- 1MB 가 넘으면 트리 대신 "너무 커서 원문만 보여요".

### 화면 (행 상세)
- JSON 칸 위에 보기 전환: **원문 · 정렬 · 트리** (마지막 선택을 기억, 기본: 트리).
  - 정렬: 들여쓰기 2칸, 키 순서는 원래 순서, 고정폭 글꼴, 선택 가능.
  - 트리: 펼치기/접기(처음엔 2단계까지 펼침), 값 종류별 색(문자 · 숫자 · 참거짓 · null), 항목 우클릭 > **값 복사** · **경로 복사**(`$.order.items[0].sku`).
- 결과 표의 JSON 칸은 그대로 원문 한 줄 (변경 없음).
- 편집 모드에서는 원문 편집만 (JSON 이 깨지면 저장 전에 "JSON 형식이 아니에요" 경고, 저장은 가능).

### 확인 기준
- 중첩 객체 · 배열 · 한글 · 이스케이프 문자가 정확히 보인다.
- 경로 복사 결과가 `$.a.b[0]` 꼴.

## F5. 이전 버전 설치

### 들어가는 곳
- 메뉴 **GodDB > 이전 버전 설치…** (Windows: 도움말 > 이전 버전 설치…)

### 목록
- GitHub 릴리스 API `GET https://api.github.com/repos/zio0911/god_db/releases` (Windows: `…/god_db_win/releases`), 인증 없음.
- 보여 줄 것: 초안 · 사전 릴리스 제외, **1.1.0 이상**, 현재 버전 제외. 최신순. 각 줄 = 버전 · 날짜 · 변경 사항 첫 3줄(릴리스 노트의 `## 변경 사항` 아래).
- 네트워크 오류면 "릴리스 목록을 가져오지 못했어요" + [GitHub 에서 직접 받기] 링크.

### 설치 흐름
1. 버전을 고르면 확인 창:
   > 1.3.6 으로 되돌릴까요? 앱을 끄고 이전 버전을 설치한 뒤 다시 켭니다. 접속 · 탭 · 설정은 그대로 남고, 설치 전에 백업합니다.
   > [ ] 이 버전에 머물기 (자동 업데이트를 '수동'으로 바꿈)  — 기본 체크
2. 열린 트랜잭션이 있으면 기존 종료 확인과 같이 먼저 묻는다.
3. 데이터 폴더 백업: `…/GodDB` → `…/GodDB-backup-<지금 버전>-<YYYYMMDD-HHmmss>` (최근 3개만 유지).
4. 내려받기 (진행률 표시, 취소 가능):
   - Mac: 릴리스의 `GodDB-<버전>.dmg`.
   - Windows: `GodDB-win-Setup.exe`.
5. 검증 — 실패하면 설치하지 않고 이유를 보여 준다:
   - Mac: DMG 를 열어 앱의 `codesign --verify --deep --strict` 통과, 서명 팀 ID 가 지금 앱과 같음, `spctl --assess` 통과(공증).
   - Windows: Authenticode 서명의 게시자가 지금 앱과 같음 (서명 없는 빌드면 SHA-256 을 릴리스 자산 정보와 비교).
6. 교체:
   - Mac: 작은 도우미 스크립트를 띄우고 앱 종료 → 도우미가 지금 앱 위치(`Bundle.main.bundleURL`)에 새 앱을 `ditto` 로 덮어쓰고 → 격리 속성 제거 → 다시 실행. 실패하면 원래 앱 그대로 두고 알림.
   - Windows: Setup.exe 를 조용히 실행(Velopack 이 같은 위치에 설치) 후 다시 실행.
7. 감사 로그: `설정 | 이전 버전 설치 1.4.0 → 1.3.6`.

### 주의 문구

## F6. 운영 접속 자동 끊기

### 설정
- 설정 > 일반 > 안전 > **운영 접속 자동 끊기**: `끔 / 10분 / 30분 / 60분` (기본 **30분**). 키 `GodDB.safety.prodIdleMinutes` (0 = 끔).

### 동작
- 대상: `environment = production` 인 접속 (SQL · Redis 모두).
- **마지막 사용 시각**: 그 접속으로 쿼리 · 명령 실행, 페이지 이동 · 이어 받기, 내보내기, 스키마 새로고침, Redis 키 조회를 한 시각. 화면을 보기만 하는 건 사용이 아니다.
- 1분마다 검사. 마지막 사용 후 설정 시간이 지나면:
  - **열린 트랜잭션(수동 커밋 변경 있음)** 이면 끊지 않는다. 대신 한 번만 알림: "운영 접속 ‹이름› 에 커밋하지 않은 변경이 있어 자동으로 끊지 않았어요" (상태창 경고 + macOS 알림).
  - 내보내기 · 쿼리 실행 중이면 끝날 때까지 미룬다.
  - 그 밖이면 연결을 끊고 상태창: "운영 접속 ‹이름› 을 30분 동안 쓰지 않아 끊었어요". 감사 로그 `접속해제 | ‹이름› | 자동 (30분 미사용)`.
- 쿼리 탭은 남는다. 다음에 실행하면 평소처럼 다시 연결한다.
- 테스트용으로 `GODDB_UI_TEST` 일 때는 `GodDB.safety.prodIdleSecondsForTest` (초) 를 쓸 수 있다.

### 확인 기준
- 개발 접속은 끊기지 않는다.
- 열린 트랜잭션이 있으면 끊지 않고 알림만 한 번.
- 끊긴 뒤 실행하면 다시 연결된다.

## F7. AI 데이터 찾기 + 테이블 메모

### 무엇을 하나
AI 어시스턴트에서 **"학년 정보는 어디 있어?" "학교 정보 어디야?"** 처럼 물으면, 그 데이터가 들어 있는 테이블 · 컬럼을 찾아 주고 실제 값으로 확인한다. 찾은 위치는 **테이블 메모**로 저장해 다음에는 AI 없이 바로 답한다.

### 들어가는 곳
- AI 어시스턴트 입력창 위 빠른 동작에 **🔎 데이터 위치 찾기** 추가 (누르면 입력 모드가 "데이터 찾기"로).
- 입력이 다음 꼴이면 자동으로 데이터 찾기로 처리: `…(은|는|이|가)? 어디(에|서)? (있|저장|들어)`, `…(어디야|어딨어)`, `where is …`, `which table …`. (판단이 애매하면 일반 질문으로)
- SQL 접속에서만. Redis · 모델링 화면에서는 버튼 숨김.

### 처리 순서
1. **메모 먼저**: 질문의 핵심어(조사 · "정보 · 데이터 · 어디 · 있어" 등을 뺀 명사)를 이 접속 · DB 의 메모 `terms` 와 비교 (정규화: 공백 제거, 소문자, 한글 그대로). 맞으면 바로 답 카드 (§답 카드), 끝. 카드에 [다시 찾기].
2. **모델 확인** (#151): 첫 AI 호출 전에 고른 모델에 `Reply with OK` (`stream:false`, `num_predict` 256, 20초). HTTP 오류 · 빈 답이면 실패. 결과는 앱을 켜 둔 동안 Ollama 주소 + 모델별로 기억 (시간 초과는 기억하지 않음).
   - 실패하면 **조용히 넘어가지 않는다**: 찾기를 멈추고 답 카드에 "선택한 AI 모델 ‹이름› 이 응답하지 않아요 (Ollama: ‹짧은 이유›). 설정 > AI 에서 다른 모델을 골라 주세요." 짧은 이유는 Ollama 응답 `{"error":"…"}` 의 글 (예: `prediction aborted, token repeat limit reached`), 120자까지.
   - 설치된 다른 모델을 뒤에서 차례로 확인해 답하는 모델마다 [‹모델› 로 바꾸기] (추천 모델 먼저). 누르면 설정의 모델을 바꾸고 같은 질문을 다시 찾는다.
   - 설정 > AI 의 [모델 확인] 이 같은 확인을 한다 (기억한 결과를 쓰지 않고 새로).
   - 모델을 고르지 않았으면(자동) 설치된 추천 모델(`qwen3:30b` → `qwen2.5-coder:14b` → `qwen2.5-coder:32b`) → 설치된 첫 모델.
3. **후보 고르기 (로컬 AI 1차)**: 로컬 Ollama 에 다음을 보내고 JSON 으로 받는다.
   - 보내는 것: 질문, 모든 테이블의 `이름 — 코멘트`, 컬럼 `이름 타입 — 코멘트` (토큰 예산 넘으면 이름 · 코멘트가 핵심어와 겹치는 테이블 우선), 기존 메모.
   - 핵심어와 함께 **약어 사전으로 넓힌 영어 이름**도 보낸다 (`학년 → grade, grd, schyr, schlyr, grde, gr, yr`).
   - 받는 형식: `{"candidates":[{"table":"…","columns":["…"],"reason":"…"}]}` 최대 5개. 응답이 형식에 안 맞으면 1회 다시 요청, 그래도 실패하면 **약어 사전 점수**(아래) 순으로 후보를 만든다. 모델이 오류(HTTP)를 내면 다시 묻지 않고 바로 약어 사전 점수로, 카드에 "AI 없이 이름 · 코멘트 · 값으로 찾은 후보예요" (+ 이유).
   - **큰 스키마 — 두 단계** (#151): 모든 테이블의 `이름 — 코멘트` + 컬럼 줄이 2만 자를 넘으면
     1. 테이블만: `이름 — 코멘트` 한 줄씩. 약어 사전 점수가 있는 테이블을 맨 앞에 두고 `[matching columns: schyr, …]` (4개까지) 를 붙인다 — 목록이 예산에서 잘려도 이 테이블들은 늘 들어간다. 받는 형식 `{"tables":["…"]}` 최대 10개.
     2. 고른 테이블 + 사전 점수 상위 3개(빠졌으면)의 컬럼 정의로 위의 후보 요청.
     칩 `테이블 목록 N개` 는 1단계에 보낸 테이블 수.
   - 없는 테이블 · 컬럼은 버린다.
   - **약어 사전** (`Sources/GodDBCore/DataFinderDictionary.swift`, 약 80개, 데이터): 항목 = 한국어 말들, 영어 이름 · 약어들, 약한 약어들(점수 절반), generic(번호 · 코드 · 이름 · 일자 · 여부 등, 가중치 0.5), 값 모양 정규식(선택). Windows 판도 같은 표를 쓴다.
     - 이름 조각: `_` `-` `.` 공백 · camelCase · 숫자 경계로 나누고 소문자. 조각이 영어 말과 같으면 일치(1), 약한 약어이거나 5글자 이상 조각이 4글자 이상 영어 말로 시작하면 0.5.
     - 질문 말 → 항목: 한국어 말과 같으면 그 항목만, 아니면 안에 든 2글자 이상 사전 말(긴 것부터, 겹치지 않게). 영어 질문 말은 그 말을 영어로 가진 항목.
     - 점수(핵심어마다 더함): 컬럼 = max(핵심어가 컬럼 코멘트에 그대로 4 | 영어 핵심어가 이름 조각과 같음 3, Σ 항목 3 × 가중치 × 일치도(이름 조각 또는 코멘트)) + 테이블 이름 · 코멘트 일치 2 × 가중치 × 일치도(최대). 컬럼 자체 점수가 0 이면 후보 아님. 이름 조각 중 맞은 조각 비율 × 0.5 를 더한다.
     - 후보 = 테이블별 컬럼 높은 순 3개, 테이블 최고 점수 순 5개.
4. **샘플 조회 (앱이 직접)**: 후보 컬럼마다
   ```sql
   -- MySQL / PostgreSQL
   SELECT <col> FROM <table> WHERE <col> IS NOT NULL LIMIT 200
   -- SQL Server: 바쁜 운영 테이블의 잠금에 막히지 않게 NOLOCK (값 몇 개를 훑는 읽기라 커밋 전 값이 섞여도 괜찮다)
   SELECT TOP 200 <col> FROM <table> WITH (NOLOCK) WHERE <col> IS NOT NULL
   ```
   - 앱에서 중복을 빼고 **최대 20개**, 값은 50자로 자름. **쿼리마다 제한 시간 10초**.
   - **따로 연 짧은 연결**에서 조회한다 (같은 주소 · 계정 · 읽기전용 세션 설정, 사용자 세션이 보던 DB/스키마로 `USE`/`search_path`). 찾기 하나 동안 다시 쓰고 끝나면 닫는다. 시간이 넘으면 그 연결의 서버 세션에 취소(MySQL `KILL QUERY`, PostgreSQL `pg_cancel_backend`, SQL Server `KILL`)를 다른 연결로 보내고 그 연결을 버린다 — 사용자 세션 · 열린 트랜잭션은 그대로. 다음 조회는 새로 연결.
   - 따로 연결을 열 수 없으면 사용자 세션으로 조회하고 시간이 넘으면 취소한다 (SQL Server 는 세션이 끊기므로 다시 연결하고 보던 DB 로 돌아간다).
   - 카드에 후보마다 조회 상태: `값 N개` / `시간 초과` / `조회 실패: …`.
   - 운영 접속이면 **접속마다 처음 한 번** 묻는다: "운영 DB 에서 후보 컬럼 값을 몇 개씩 조회해 로컬 AI 에 보낼까요?" [이번만] [이 접속은 항상] [취소].
   - 읽기전용 접속도 조회라 가능.
5. **판단 (로컬 AI 2차)**: 질문 + 후보 + 샘플 값을 보내고 JSON 으로 받는다:
   `{"table":"…","columns":["…"],"confidence":"high|medium|low","explain":"…","sql":"SELECT …"}`
   - 값 모양이 있는 핵심어면 샘플 아래 `hint: values look like 학년` / `values do not look like 학년` (80% 이상 맞음 / 하나도 안 맞음).
   - `sql` 은 SELECT 만 허용 (아니면 버리고 `SELECT * FROM <table>` 로).
   - 형식이 틀리거나 모델 오류면, 또 3단계에서 모델 오류가 났으면 AI 없이: 사전 점수 + 값 모양(맞음 +3, 안 맞음 −3) 1등, 신뢰도 낮음.
6. **답 카드** 표시 + **메모 자동 저장** (아래).

### 답 카드
```
┌ 🔎 학년 정보 ───────────────────────────────┐
│ tb_student.grade_cd   신뢰도 높음  (AI · 미확인) │
│ 값 예: 1, 2, 3, 4, 5, 6                         │
│ 학생 테이블의 학년 코드예요. 코멘트 '학년코드'… │
│ [데이터 보기] [SQL 넣기] [맞아요] [아니에요]    │
│ 다른 후보: tb_class.grade (중간)                 │
└──────────────────────────────────────────────────┘
```
- [데이터 보기]: 새 탭에서 `sql`(또는 `SELECT * FROM table`) 실행.
- [맞아요]: 메모를 **확인됨**으로. [아니에요]: 이 메모를 지우고 다음 후보를 보여 준다 (없으면 "다른 후보가 없어요").
- 보낸 내용 칩: `테이블 목록 N개` `후보 컬럼 샘플 M개 (로컬)`.

### 테이블 메모
- **자동 저장**: 답 카드가 나오면 `{terms:[질문 핵심어], table, columns, memo: explain, source:"ai", confirmed:false}` 로 저장. 같은 table+columns 메모가 있으면 terms 만 합친다.
- **보기 · 고치기**: 사이드바 테이블 옆 📝(메모가 있으면), 우클릭 > **테이블 메모…** → 그 테이블의 메모 목록: 찾는 말(쉼표), 컬럼, 설명, 확인됨 체크, 삭제. 직접 추가도 가능 (`source:"user"`, 확인됨).
- **AI 문맥에 포함**: 일반 어시스턴트 질문에도 이 DB 의 메모(최대 50개)를 "팀이 확인한 위치" 로 함께 보낸다.

### 저장 형식 (Mac · Windows 동일)
- Mac `~/Library/Application Support/GodDB/table-notes.json`, Windows `%APPDATA%\GodDB\table-notes.json`, 권한 본인만.
```json
{
  "version": 1,
  "notes": [
    {
      "id": "8C1F…UUID",
      "profileID": "UUID",
      "database": "school",
      "table": "tb_student",
      "columns": ["grade_cd"],
      "terms": ["학년"],
      "memo": "학생 테이블의 학년 코드 (1~6)",
      "source": "ai",
      "confirmed": false,
      "createdAt": "2026-11-20T10:00:00Z",
      "updatedAt": "2026-11-20T10:00:00Z"
    }
  ]
}
```
- 샘플 값은 저장하지 않는다.

### 개인정보 · 안내 문구 변경
- 어시스턴트 하단 안내를 바꾼다:
  > 구조 · 코멘트 · 통계 · SQL 을 로컬 Ollama 에 보내요. **데이터 찾기**에서는 후보 컬럼의 값 몇 개(최대 20개)도 로컬 Ollama 에 보내요. 이 PC 밖으로는 나가지 않아요.
- 시스템 프롬프트의 "You never see row data" 를 "You see only small samples of candidate columns in data-finding mode" 로 맞춘다.

### 감사 로그
- `AI | <접속>/<DB> | 데이터 찾기 · 후보 N · 샘플 조회 M | (질문 · 값은 남기지 않음)`.
- 샘플 조회 SQL 자체는 평소처럼 `조회` 줄로 남는다.

### 확인 기준
- 테스트 DB 에 코멘트가 있는 `ui_students(grade_cd '학년코드')`, `ui_schools(school_nm '학교명')` 를 두고 "학년 정보는 어디 있어?" → `ui_students.grade_cd` (Ollama 가 있을 때만 통합 테스트).
- 같은 질문을 다시 하면 AI 호출 없이 메모로 답한다.
- [아니에요] 하면 메모가 지워지고 다른 후보가 나온다.
- Ollama 없이 단위 테스트: 핵심어 추출, 메모 일치, 후보 JSON 파싱 · 검증, 샘플 SQL 생성(3종 DB, SQL Server NOLOCK), 약어 사전 이름 조각 · 일치, 2단계 요청 만들기, 값 모양, 모델 확인(가짜 전송).
- 큰 스키마 실제 확인 (#151, `GODDB_DATAFINDER_LIVE=1`): 약 150개 약어 테이블(`tb_stdnt_info(stdnt_no, stdnt_nm, schyr, …)` 등, 코멘트 대부분 없음)에서 "학년 정보는 어디 있어?" → `tb_stdnt_info.schyr`, "학교 이름은 어디야?" → `tb_schl_info.schl_nm`, "회원 전화번호 어디 있어?" → `tb_mbr_info.mbr_tel_no` (SQL Server · MySQL, qwen3:30b). AI 없이도 같은 답. 고장 난 모델은 확인에서 실패하고 이유가 보인다.

## F9. 보안 강화

> 2026-11-20 보안 검토 지적 4건 반영. 방향: **클라이언트에서 할 수 있는 만큼 최대한.**

### F9-1. Ollama 는 이 PC 만
- 허용 주소: 호스트가 `localhost`, `127.0.0.0/8`, `::1` 인 `http(s)://…` 만. 그 밖은 설정에서 저장되지 않고 안내:
  > AI 는 이 PC 의 Ollama 만 쓸 수 있어요. 다른 서버로는 구조 · SQL · 샘플 값이 나가므로 막아 두었어요.
- 이미 원격 주소가 저장돼 있으면(업데이트 직후) AI 기능을 끄고 설정 > AI 에 같은 안내 + [기본값(localhost)으로]. 
- 요청 직전에도 한 번 더 검사 (`OllamaClient` 에서 원격이면 요청하지 않고 오류) — 설정을 우회해도 막힌다.

### F9-2. SQL Server 읽기전용 안내
- SQL Server 에는 세션 단위 읽기전용이 없어 서버에서 강제할 방법이 없다 (MySQL · PostgreSQL 은 세션 `READ ONLY` 로 이중 차단).
- 접속 편집에서 SQL Server + 읽기전용을 켜면 그 아래:
  > SQL Server 는 앱에서만 막아요(서버에서 강제되지 않음). 운영 DB 는 **읽기 권한만 있는 DB 계정**을 쓰세요.
- FEATURES.md 알려진 제약 · 보안 설명에도 같은 내용.

### F9-3. TLS 서버 인증서 확인 (MySQL · PostgreSQL · Redis · SQL Server)
- 접속 편집 TLS 옆 **서버 인증서 확인** (기본 **켬**, 기존 접속도 켬으로).
- **직접 접속(SSH 없이)** 일 때:
  1. 시스템 신뢰 저장소로 인증서 체인 + 호스트 이름 확인 → 통과하면 연결.
  2. 실패하면(사설 인증서 · IP 접속 · 이름 불일치) 확인 창:
     ```
     ⚠ 서버 인증서를 확인할 수 없어요 — ‹접속 이름›
     주체: CN=…   발급: …   유효: 2026-01-01 ~ 2027-01-01
     SHA-256: 3F:A2:…:9C
     이유: 신뢰할 수 없는 발급자 / 이름이 다름 / 만료됨
     처음 연결하는 서버라면, 관리자에게 받은 지문과 같은지 확인하세요.
     [취소]  [이 인증서 신뢰 (고정)]
     ```
  3. 신뢰하면 그 인증서(맨 앞, DER)의 SHA-256 을 접속 정보에 저장(`tlsPinSHA256`). 다음부터 체인 확인이 실패해도 **지문이 같으면 연결**.
  4. 지문이 바뀌면 연결하지 않는다:
     > 서버 인증서가 바뀌었어요. 서버를 교체한 게 아니라면 중간에서 가로채는 공격일 수 있어요. 관리자에게 확인한 뒤 [저장된 인증서 지우기] 를 누르세요.
- **SSH 터널 경유**: 터널 안쪽은 `127.0.0.1` 이라 이름 확인을 하지 않는다 (SSH 가 서버 확인 · 암호화를 담당 — F9-4). 고정 지문이 있으면 지문만 확인.
- **PostgreSQL**: TLS 를 켜면 **반드시 TLS** (지금의 "가능하면 TLS" 대신). 서버가 TLS 를 안 하면 "서버가 TLS 를 지원하지 않아요. TLS 를 끄거나 SSH 터널을 쓰세요."
- **SQL Server** (1.4.1 #157에서 추가, 처음에는 암호화만 했음): 다른 DB 와 같은 규칙 · 확인 창 · 상태창. 접속 편집의 "암호화만" 안내는 없앴다.
  - FreeTDS 1.5 가 할 수 있는 것: freetds.conf 의 `encryption = off|request|require|strict`, `ca file`(경로 또는 `system`), `crl file`, `check certificate hostname`, `certificate hostname`. `ca file` 을 넣어야만 인증서를 확인한다 (없으면 암호화만). 확인 콜백 · 지문 비교 · 로그인별 CA 옵션(DB-Library `DBSET…`)은 없다. 설정 파일은 `FREETDSCONF` 환경 변수나 `dbsetifile()` 로 프로세스 전체에 하나.
  - 그래서 두 단계:
    1. **미리 받기** — 연결할 IP · 포트에 PRELOGIN(VERSION · ENCRYPTION=ON · INSTOPT · THREADID · MARS) → 응답의 ENCRYPTION 이 NOT_SUP 이면 "서버가 TLS 를 지원하지 않아요" → 아니면 TLS 핸드셰이크. TDS 7.x 라 TLS 레코드를 PRELOGIN 패킷(0x12, 8바이트 머리, 마지막에 EOM)에 감싸 주고받는다. 인증서를 받으면 위 판정을 하고 끊는다 (로그인 안 함).
    2. **FreeTDS 연결** — 같은 IP · 포트. 연결마다 고유 섹션(`[goddb-<uuid>]`: host · port · `tds version = 7.4` · `encryption = require` · `ca file` · 이름 확인)을 넣고, 서버 이름 대신 섹션 이름으로 연다.
       - 시스템 신뢰 저장소 통과 → `ca file` = OS 시스템 루트 + OS 가 만든 체인, `check certificate hostname = yes`, `certificate hostname = <접속 호스트>`.
       - 고정 인증서 → 서버가 보낸 체인이 자체 서명으로 끝나고 유효 기간 안이면 `ca file` = 그 체인, 이름 확인 안 함. 아니면 `ca file` 없이 암호화만.
       - SSH 터널 · 고정 없음 → 미리 받지 않음, 암호화만.
  - 설정 파일 하나(임시 폴더, 0600)를 처음에 `dbsetifile` 로 지정하고 섹션을 넣고 뺄 때 통째로 새로 써서 rename. 섹션 · CA 파일은 연결 시도가 끝나면 지운다. 환경 변수를 연결마다 바꾸지 않아 동시 연결이 안전하고, 연결을 직렬로 묶지 않는다.
  - 제약: 두 연결 사이에 인증서가 바뀌면 `ca file` 로 다시 확인하는 경우는 FreeTDS 가 거부하지만, FreeTDS 는 지문 비교를 못 해서 같은 CA 의 다른 인증서는 통과한다. 자체 서명으로 끝나지 않는 고정 체인은 그 틈을 막지 못한다. TDS 8 strict 전용 서버는 지원하지 않는다 (FreeTDS 연결이 `require`).
  - Windows: 드라이버가 인증서 확인 콜백을 주면 그걸로 같은 판정을 하면 된다 (미리 받기 불필요). 콜백이 없는 드라이버면 같은 두 단계.
- 연결 후 상태창에 한 줄: `TLS 사용 · 인증서 확인됨` / `TLS 사용 · 고정 인증서` / `TLS 사용 · 확인 안 함(SSH 터널)` / `TLS 사용 · 확인 안 함` / `TLS 안 씀` (SQL Server 도 같음).
- 감사 로그: `설정 | ‹접속› | TLS 인증서 신뢰 SHA256:…` / `인증서 고정 지움`.
- 구현 메모 (Mac): NIOSSL 의 사용자 정의 확인 콜백(`NIOSSLCustomVerificationCallback`)으로 "체인 확인 → 실패 시 지문 비교". mysql-nio · postgres-nio 는 `Vendor/` 패치로 콜백을 넘긴다 (GODDB_PATCH.md 에 기록). Windows 는 `SslStream` 의 `RemoteCertificateValidationCallback` 으로 같은 규칙.

### F9-4. SSH 호스트 키 확인
- 지금 `StrictHostKeyChecking=accept-new` (처음 키를 묻지 않고 저장) → **처음 접속 때 지문을 보여 주고 확인**받는다.
  1. 연결 전에 `ssh-keygen -F '[host]:port'` 로 `~/.ssh/known_hosts` 와 GodDB 전용 `known_hosts` 에서 찾는다.
  2. 없으면 `ssh-keyscan -p <port> <host>` 로 키를 받고 `ssh-keygen -lf -` 로 지문(SHA256) 계산 → 확인 창:
     ```
     처음 접속하는 SSH 서버예요 — bastion.example.com:22
     ED25519  SHA256:9cP3…xk
     서버 관리자에게 받은 지문과 같은지 확인하세요.
     [취소]  [신뢰하고 연결]
     ```
  3. 신뢰하면 GodDB 전용 `known_hosts`(Mac `~/Library/Application Support/GodDB/known_hosts`, Windows `%APPDATA%\GodDB\known_hosts`, 권한 본인만)에 추가.
- ssh 실행 옵션: `-o StrictHostKeyChecking=yes -o UserKnownHostsFile="~/.ssh/known_hosts <GodDB known_hosts>"`.
- 키가 바뀌면 ssh 가 거부 → 안내:
  > SSH 서버 키가 바뀌었어요. 서버를 다시 설치한 게 아니라면 중간에서 가로채는 공격일 수 있어요. 관리자에게 확인한 뒤 [저장된 키 지우기] (GodDB 전용 파일에서만 지움).
- 감사 로그: `설정 | SSH 호스트 키 신뢰 host:port SHA256:…`.

### F9 확인 기준
- 원격 Ollama 주소는 저장 · 요청 모두 막힌다 (단위 테스트: 주소 판정).
- TLS: 공인 인증서 서버는 묻지 않고 연결, 자체 서명 서버는 확인 창 → 고정 후 재접속 시 묻지 않음, 다른 인증서로 바꾸면 거부 (Docker 테스트 DB 에 자체 서명 인증서로 확인).
- PostgreSQL 은 TLS 를 켜고 TLS 없는 서버에 붙으면 오류.
- SSH: 모르는 서버는 확인 창, 신뢰 후 재접속 시 묻지 않음, 키 변경 시 거부 (테스트용 sshd 컨테이너).
